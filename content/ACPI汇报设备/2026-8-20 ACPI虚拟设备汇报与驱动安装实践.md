## 目标

1. 固件侧独立 Module（`OemJYTianPkg\JYTianVirtualDevice`）通过 ACPI 汇报虚拟设备
2. 编译驱动安装，设备管理器无黄标

## 固件侧

### MyVirtualDeviceSsdt.asl

```asl
DefinitionBlock ("MyVirtualDeviceSsdt.aml", "SSDT", 2, "AMI", "JYTVDV01", 1) {
    Scope (\_SB) {
        Device (VDV0) {
            Name (_HID, "VDV0001")            // INF 按它匹配
            Name (_CID, "PNP0C02")            // 兼容 ID：内置驱动兜底
            Name (_UID, 0)
            Name (_STA, 0x0F)
        }
    }
}
```

### MyVirtualDevice.c（注入逻辑）

```c
Status = gBS->LocateProtocol (&gEfiAcpiTableProtocolGuid, NULL, (VOID**)&AcpiTableProtocol);
// 循环 GetSectionFromFv 扫自身 FFS 的 RAW 段
while (TRUE) {
  Status = GetSectionFromFv (&gEfiCallerIdGuid, EFI_SECTION_RAW, SectionInstance++,
                             (VOID**)&Table, &TableSize);
  if (EFI_ERROR (Status)) break;
  if (Table->OemTableId == SIGNATURE_64('J','Y','T','V','D','V','0','1')) {
    Status = AcpiTableProtocol->InstallAcpiTable (AcpiTableProtocol, Table, TableSize, &TableKey);
    break;
  }
}
```

### MyVirtualDeviceFdfRule.txt（RAW 段打包规则）

```ini
[Rule.Common.DXE_DRIVER.MY_VD_SSDT]
  FILE FREEFORM = $(NAMED_GUID) {
    DXE_DEPEX DXE_DEPEX Optional    $(INF_OUTPUT)/$(MODULE_NAME).depex
    PE32      PE32                  $(INF_OUTPUT)/$(MODULE_NAME).efi
    RAW ACPI  Optional              $(INF_OUTPUT)/$(MODULE_NAME).aml
  }
```

### 固件侧

| 现象 | 根因 | 修复 |
|---|---|---|
| 构建报 File open failure | FDF 规则文件含 **UTF-8 中文注释**，编译终端 GBK 解码炸 | 全部构建文件纯 ASCII（工程现有代码本就全 ASCII） |
| `InstallAcpiTable: Invalid Parameter` | 第 4 参 TableKey 传 NULL（必填 OUT 参） | `UINTN TableKey;` 传 `&TableKey` |
| 编译 C4133 UINT32* → UINTN* | 本工程 AMI 移植版 TableKey 是 `UINTN*`（标准 EDK2 是 UINT32*） | 类型改 `UINTN` |


## 驱动侧


### MyVdDriver.c（核心）

```c
DriverEntry:
  DriverObject->DriverUnload          = MyVdUnload;
  DriverObject->DriverExtension->AddDevice = MyVdAddDevice;
  DriverObject->MajorFunction[IRP_MJ_PNP] = MyVdPnp;
  return STATUS_SUCCESS;

MyVdAddDevice:                        // 
  IoCreateDevice (DriverObject, 0, NULL, FILE_DEVICE_UNKNOWN, 0, FALSE, &DeviceObject);
  DeviceObject->Flags |= DO_BUFFERED_IO;
  DeviceObject->Flags &= ~DO_DEVICE_INITIALIZING;
  return STATUS_SUCCESS;

MyVdPnp:
  case IRP_MN_START_DEVICE:           // 直接成功 = 设备启动
    Irp->IoStatus.Status = STATUS_SUCCESS; IoCompleteRequest (Irp, IO_NO_INCREMENT);
    return STATUS_SUCCESS;
  default:                            // 其余 PnP IRP 转发下行
    IoSkipCurrentIrpStackLocation (Irp);
    return IoCallDriver (IoGetAttachedDeviceReference (DeviceObject), Irp);
```

### 签名（关键：SHA-256 证书）

```powershell
# makecert 只支持 SHA-1，Win10 1607+ 拒绝 SHA-1 内核驱动签名 → 用 PowerShell
$c = New-SelfSignedCertificate -Type CodeSigningCert -Subject 'CN=JYTian Test Cert' `
  -CertStoreLocation Cert:\CurrentUser\My -HashAlgorithm SHA256 `
  -TextExtension @('2.5.29.37={text}1.3.6.1.5.5.7.3.3,1.3.6.1.4.1.311.10.3.5')
Export-Certificate -Cert $c -FilePath MyVdDriverTest.cer -Force
# 签名
signtool sign /v /s My /n "JYTian Test Cert" /fd sha256 /t http://timestamp.digicert.com MyVdDriver.cat MyVdDriver.sys
```

### 驱动侧排错（按时间线）

| 版本 | 现象 | 根因 | 修复 |
|---|---|---|---|
| KMDF 初版 | `'cl' 不是内部或外部命令` | vcvarsall 从 PowerShell 静默失效 | 手动设置 PATH/INCLUDE/LIB |
| KMDF 初版 | WdfVersion* unresolved | 缺 WdfLdr.lib | 补 WdfLdr.lib |
| 1.0.0.1 | 驱动日期"不可用" | 缺 .rc 版本资源 | 补 version resource |
| 1.0.0.2 | 每次安装 0xE0000219，从未加载 | **link 默认 /OPT:REF 删掉 WDFLDR 导入表**，.sys 无导入表 | link 加 /OPT:NOREF |
| 1.0.0.2 | 重装仍失败 | 设备节点带 ConfigFlags=0x20 烙印 | 卸载设备（删驱动）→ 扫描重建节点 |
| 1.0.0.4 | 对齐同事代码 | 改 WDM 不 attach + ASL 加 _CID PNP0C02 | 重写驱动 + 改 ASL |
| 1.0.0.5 | 签名检查 | 证书 SHA-1，Win11 拒绝 | SHA-256 + KMCS EKU 证书 |
| 1.0.0.6 | 更新驱动报"缺少必要的条目" | **%SPSVCINST_ASSOCSERVICE% 未在 [Strings] 定义**，Services 段作废 | 补定义（infverif 一锤定音） |



1. AMI 构建消费的文本文件（fdf 规则/sdl/cif/inf/asl/c）全部纯 ASCII
2. 手动 cl/link 编驱动先查导入表：`dumpbin /imports`；KMDF 裸链接必须 `/OPT:NOREF`
3. 自签内核驱动证书必须 SHA-256 + KMCS EKU；`signtool verify /v` 看 `Hash of file (sha256)` 确认
4. **INF 装前必跑 infverif**：`tools\x86\infverif.exe /v /info xxx.inf`（pnputil/Inf2Cat 对 %SPSVCINST_ASSOCSERVICE% 未定义都不报，设备管理器装时才炸）
5. 安装失败的设备节点带 `ConfigFlags=0x20`，不删节点重装永远失败
6. Secure Boot 开时 TESTSIGNING 被拒，先 `bcdedit /enum | findstr testsigning` + `Confirm-SecureBootUEFI`
7. 排错信息源：`C:\Windows\INF\setupapi.dev.log` > 设备事件 > 设备管理器外观（Win11 蓝问号会误导，曾多次被误判为"驱动已加载"）

## 术语表

| 术语 | 含义 |
|---|---|
| SSDT | 辅助 ACPI 表，可由 DXE 驱动运行期注入 |
| _HID / _CID | 硬件 ID / 兼容 ID |
| ConfigFlags 0x20 | 设备安装失败的注册表烙印 |
| KMCS EKU | 内核模式代码签名（1.3.6.1.4.1.311.10.3.5） |
