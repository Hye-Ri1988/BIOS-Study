# BDS — Boot Device Selection

## BDS 在整个启动流程里的位置

```
SEC → PEI → DXE → BDS → OS/Shell → Runtime
```

BDS 不是独立固件阶段，是 **DXE 阶段内部的一个环节**。DXE Core 调度完所有满足 Depex 的驱动后，通过 EFI_BDS_ARCH_PROTOCOL 调用 BdsEntry()，把控制权交给 BDS。

## BDS 的核心任务

三件事：**连接设备、管理启动选项、加载操作系统**。

- 设备连接：PCI 总线枚举、显卡和控制台初始化、存储设备扫描、USB 键盘鼠标连接
- 启动管理：从 NVRAM 读 BootOrder 和 BootXXXX 变量、构建 Boot Option 列表、匹配设备和启动选项、按优先级启动
- 用户交互：Setup 菜单、Boot Manager、超时自动选择

## BDS 启动流程 10 步

1. DXE Core 调 BdsEntry()
2. 初始化 NVRAM 变量（Timeout、OsIndications）
3. 确定 Boot Mode 和 Execution Policy
4. Signal EndOfDxe，SMM Ready to Lock
5. Re-Dispatch 待处理的 DXE 驱动（Depex 里写了 END_OF_DXE 的）
6. 连接所有设备驱动
7. 连接控制台（ConOut、ConIn、ErrOut）
8. 更新 Boot Option 变量和 HII 字符串
9. 进 Setup 或直接启动
10. Boot() → BootEfi() 加载 OS

## BdsControlFlowFunctions 数组

BDS 的核心调度机制。BdsEntry() 里一个 for 循环遍历这个函数指针数组，按顺序执行每个控制流函数。数组在 BdsBoard.c 里定义，通过 eLink 宏在编译时注入平台特定函数。

主要函数：SignalEndOfDxe()、CallTheDispatcher()、ConnectEverything()、ConnectConOut/ConIn()、UpdateBootOptionVariables()、HandoffToTse()。

## Boot Option 数据结构和管理流程

- **BootOrder**：NVRAM 里的 UINT16 数组，指定启动顺序
- **BootXXXX**：每个启动选项的详细配置，EFI_LOAD_OPTION 格式
- **内存中**：用 BOOT_OPTION 结构体的双向链表管理，字段有 Attributes、Description、FilePathList、BootOptionNumber、Priority、Tag 等

**管理流程**：ReadBootOptions() 从 NVRAM 读 → CollectBootDevices() 枚举物理设备 → MatchOptionsToDevices() 匹配 → NormalizeBootOptions() 生成可读名称 → SaveBootOptions() 写回 NVRAM → Boot() 按优先级启动。

> ReadBootOptions() 里有一个小写 hex 兼容处理：部分 OS 用 Boot0001（小写），正常读 Boot0001 找不到时会降级用小写重试。

## Boot() 的分发逻辑

Boot() 从 EFI_LOAD_OPTION 解析 Device Path，判断类型：

- **非 BBS 类型** → BootEfi()：调 gBS->LoadImage() 加载 EFI 镜像再 gBS->StartImage() 启动。还会尝试分区发现，找 `\EFI\BOOT\BOOTX64.EFI` 作为默认路径
- **BBS 类型** → BootLegacy()：用 INT 19h 中断启动传统 OS

## HII 在 BDS 里的作用

HII（Human Interface Infrastructure）是 UEFI 的 UI 框架，BDS 用它生成启动选项名称和构建 Setup 里的 Boot 页面。

- **VFR**：声明式语法，描述 Setup 界面结构（formset、varstore、form、goto、checkbox），编译生成 .ifr 二进制
- **UNI**：多语言字符串，VFR 通过 STRING_TOKEN 引用。Bds.uni 定义了 HD、USB、NET 等设备类型名称，BDS 拼接前缀加设备名生成可读的启动选项名称
- **ConfigAccess callback**：处理 Setup 菜单里用户修改启动顺序的回调

驱动加载时通过 AmiPublishHiiResources() 注册 HII 包到 HII Database。核心调用是 HiiDatabase->NewPackageList()，把 VFR/UNI 资源注册进去。

## Driver Binding 协议

每个 UEFI 驱动安装 EFI_DRIVER_BINDING_PROTOCOL，三个核心函数：

- **Supported**：探测能否管理某个控制器
- **Start**：绑定并安装协议（如 BlockIo）
- **Stop**：解绑卸载

Version 字段控制绑定优先级，高版本优先。BDS 的 ConnectEverything() 通过 gBS->ConnectController() 触发这个流程。
