# INF & DEC 文件详解

## EDK2 构建系统

构建流程（从源码到 .efi 镜像）：

```
DSC + DEC + INF → Build Tool → AutoGen.c/h → Compiler → .efi → FDF → FD 镜像
```

四个核心元数据文件的职责：

| 文件 | 职责 |
| --- | --- |
| DSC | 平台配置，定义构建哪些模块 |
| DEC | Package 声明，提供 GUID/PCD/Include |
| INF | Module 描述，定义单个模块的属性 |
| FDF | Flash 布局，定义 Region 和 FV |

核心关系：DSC 引用 INF 确定构建哪些模块 → INF 引用 DEC 查找 GUID/Protocol/PCD 定义 → DEC 定义共享接口和数据结构。

## INF & DEC 核心概念

### INF — Module Information File

模块描述文件，每个 Module 对应一个。主要 Section：

- `[Defines]` — BASE_NAME, FILE_GUID, MODULE_TYPE
- `[Sources]` — .c / .h 源文件列表
- `[Packages]` — 引用哪些 DEC 包
- `[LibraryClasses]` — 依赖哪些 Library
- `[Guids/Protocols/Ppis]` — 使用哪些 GUID/Protocol
- `[Pcd*]` — 使用哪些 PCD
- `[Depex]` — 依赖表达式（加载条件）

### DEC — Package Declaration File

包声明文件，每个 Package 对应一个。主要 Section：

- `[Defines]` — 包名 + GUID + 版本
- `[Includes]` — 头文件搜索路径
- `[LibraryClasses]` — 提供哪些 Library 接口
- `[Guids]` / `[Protocols]` / `[Ppis]` — GUID 值声明（CName = {...}）
- `[Pcds*]` — PCD 类型与默认值

> INF 声明"我要用什么"，DEC 声明"我提供什么"，两者通过 Packages / Guids / LibraryClasses 串联。

### INF vs DEC 对比

| 对比维度 | INF 文件 | DEC 文件 |
| --- | --- | --- |
| 文件粒度 | 单个 Module | 整个 Package |
| 谁引用谁 | INF [Packages] 引用 DEC | DEC 独立存在 |
| 编译角色 | 生成 AutoGen + Makefile | 提供 AutoGen 查找资源 |
| Section 大小写 | 敏感 | 敏感 |
| 手动编辑 | 新增功能时需要 | 有变更需审核（SDL） |

## MODULE_TYPE

UEFI 启动阶段顺序：SEC → PEI → DXE → BDS → TSL → RT。

| 模块 | 执行阶段 | 入口 | 通信机制 | 典型用途 | INF MODULE_TYPE |
| --- | --- | --- | --- | --- | --- |
| PEIM | PEI | PeimEntryPoint | PPI | 内存初始化、CPU Init | PEIM |
| DXE Driver | DXE | EntryPoint (EfiMain) | Protocol | 大多数设备驱动 | DXE_DRIVER |
| SMM Driver | SMM（特殊） | EntryPoint | SMM Protocol | 安全擦写、硬件监控 | DXE_SMM_DRIVER |
| UEFI Driver | BDS/TSL | EntryPoint | Protocol | GOP、键盘、Shell 工具 | UEFI_DRIVER |
| LIBRARY | 不独立运行 | 无 | 被链接调用 | 代码共享 | 含 LIBRARY_CLASS 字段 |

LIBRARY 特殊点：不独立运行，被其他 Driver 链接使用；INF 特殊字段 `LIBRARY_CLASS = MyLib`；由 DSC [LibraryClasses] 映射到具体实现。

### 模块类型选择指南

1. 需要提前初始化硬件？→ **PEIM**（PREMEM / POSTMEM）
2. 否，运行时访问固件服务（安全）？→ **SMM**（DXE_SMM_DRIVER）
3. 否，标准设备驱动？→ **DXE_DRIVER**（注册 Protocol 提供服务）
4. 否，UEFI 界面驱动？→ **UEFI_DRIVER**（GOP、Input、文件系统，遵循 Driver Model，Start/Stop 绑定）
5. 否，只是共享代码？→ **LIBRARY**（INF 声明 LIBRARY_CLASS，DSC 指定实现）

## PEIM 创建

```ini
## MyPeiModule.inf
[Defines]
  INF_VERSION     = 0x00010005
  BASE_NAME       = MyPeiModule
  FILE_GUID       = A1B2C3D4-E5F6-7890-A1B2-C3D4E5F67890
  MODULE_TYPE     = PEIM
  VERSION_STRING  = 1.0
  ENTRY_POINT     = MyPeiModuleEntry
[Sources]
  MyPeiModule.c
[Packages]
  MdePkg/MdePkg.dec
```

```c
// MyPeiModule.c
#include <PiPei.h>
#include <Library/DebugLib.h>
#include <Library/PeiServicesLib.h>

EFI_STATUS
EFIAPI
MyPeiModuleEntry (
  IN EFI_PEI_FILE_HANDLE      FileHandle,
  IN CONST EFI_PEI_SERVICES   **PeiServices
  )
{
  DEBUG ((DEBUG_INFO, "My PEIM Loaded!\n"));
  return EFI_SUCCESS;
}
```

PEIM 特点：入口函数带 PeiServices 参数；用 PPI 与其他 PEIM 通信（不能用 Protocol）；可选 PREMEM/POSTMEM；通常有独立 [Depex]。

常见 PEIM：CpuPei、MemoryInit PEIM、PlatformPei、FvFileLoader。

> 注意：PEI 阶段堆栈尚未完全初始化，部分 Library 服务不可用，需注意 Library 的可用阶段限制。

**创建流程**：编写 .c（含 PiPei.h，实现入口）→ 编写 .inf（MODULE_TYPE=PEIM，ENTRY_POINT 与函数名一致）→ DSC 注册 → Build。

## DXE Driver 创建

```ini
## MyDxeDriver.inf
[Defines]
  INF_VERSION     = 0x00010005
  BASE_NAME       = MyDxeDriver
  FILE_GUID       = D1E2F3A4-B5C6-7890-D1E2-F3A4B5C67890
  MODULE_TYPE     = DXE_DRIVER
  VERSION_STRING  = 1.0
  ENTRY_POINT     = MyDxeDriverEntry
[Sources]
  MyDxeDriver.c
  ComponentName.c
[Packages]
  MdePkg/MdePkg.dec
  MdeModulePkg/MdeModulePkg.dec
```

```c
// MyDxeDriver.c
#include <Uefi.h>
#include <Library/UefiBootServicesTableLib.h>
#include <Library/DebugLib.h>
#include <Library/UefiLib.h>

EFI_STATUS
EFIAPI
MyDxeDriverEntry (
  IN EFI_HANDLE        ImageHandle,
  IN EFI_SYSTEM_TABLE  *SystemTable
  )
{
  DEBUG ((DEBUG_INFO, "My DXE Driver Loaded!\n"));
  return EFI_SUCCESS;
}
```

与 PEIM 的关键差异：参数不同（ImageHandle + SystemTable）；通信用 Protocol（PEI 用 PPI）；服务更多（BootServices/RuntimeServices）；有完整内存管理（Heap 可用）。

### 两种模式

- **Driver Binding 模式**（推荐，大多数设备驱动）：注册 `gEfiDriverBindingProtocolGuid`，实现 Supported()/Start()/Stop() 三个函数
- **简单初始化模式**（非设备驱动的服务模块）：入口直接初始化硬件、注册服务 Protocol、安装 Config Table，不实现 Driver Binding

## SMM Driver 创建

```ini
## MySmmDriver.inf
[Defines]
  INF_VERSION     = 0x00010005
  BASE_NAME       = MySmmDriver
  FILE_GUID       = B1C2D3E4-F5A6-7890-B1C2-D3E4F5A67890
  MODULE_TYPE     = DXE_SMM_DRIVER
  VERSION_STRING  = 1.0
  ENTRY_POINT     = MySmmDriverEntry
[Sources]
  MySmmDriver.c
[Packages]
  MdePkg/MdePkg.dec
  MdeModulePkg/MdeModulePkg.dec
```

SMM 特有操作：`gSmst`（SMM Services Table）、SmmAllocatePool/SmmFreePool、SmiHandlerRegister、访问 SMRAM。

构建注意事项：头文件用 PiSmm.h（不是 Uefi.h）；Library 需选 SMM 版本；使用 SmmServicesTableLib。

典型场景：BIOS 运行时保护（Secure Flash）、硬件安全监控（TPM、温度）、电源管理、SMI Handler 响应事件。

与传统 DXE 的 INF 差异：MODULE_TYPE = DXE_SMM_DRIVER；[Depex] 通常依赖 gEfiSmmBase2ProtocolGuid；不能直接访问常规内存，须用 SMRAM。

**DXE → SMM 通信**：SMM 驱动分两部分（SMM 本体 + DXE 入口）；DXE 通过 SMM Communication Protocol 发数据；SMM 通过 SMI Handler 接收；数据经 Comm Buffer 交换。

## UEFI Driver 创建

```ini
## MyUefiDriver.inf
[Defines]
  INF_VERSION     = 0x00010005
  BASE_NAME       = MyUefiDriver
  FILE_GUID       = C1D2E3F4-A5B6-7890-C1D2-E3F4A5B67890
  MODULE_TYPE     = UEFI_DRIVER
  VERSION_STRING  = 1.0
  ENTRY_POINT     = MyUefiDriverEntry
  UNLOAD_IMAGE    = MyUefiDriverUnload
[Sources]
  MyUefiDriver.c
  ComponentName.c
[Packages]
  MdePkg/MdePkg.dec
```

DXE_DRIVER vs UEFI_DRIVER：
- DXE_DRIVER 由 DXE Dispatcher 自动加载；UEFI_DRIVER 在 BDS 阶段或 Shell 加载
- DXE_DRIVER 必须有 [Depex]；UEFI_DRIVER 可选
- UEFI_DRIVER 支持 UNLOAD；DXE 通常不支持
- UEFI_APPLICATION 用于 Shell 应用程序

### MODULE_TYPE 速查

| MODULE_TYPE | 入口 | 通信/特点 |
| --- | --- | --- |
| PEIM | PeimEntryPoint | 通信用 PPI |
| DXE_DRIVER | ImageHandle + SystemTable | 用 Protocol |
| DXE_SMM_DRIVER | 同 DXE | PiSmm.h + gSmst |
| UEFI_DRIVER | 同 DXE | 支持 UNLOAD_IMAGE |

## LIBRARY Module 创建

```ini
## MyLib.inf
[Defines]
  INF_VERSION    = 0x00010005
  BASE_NAME      = MyLib
  MODULE_TYPE    = BASE
  LIBRARY_CLASS  = MyLib | MyLib.h
[Sources]
  MyLib.c
[Packages]
  MdePkg/MdePkg.dec
```

LIBRARY 独有特性：声明 `LIBRARY_CLASS = ClassName | HeaderPath`；不需要 ENTRY_POINT；MODULE_TYPE 通常为 BASE；DSC [LibraryClasses] 指定实现；LIBRARY 可以调用其他 LIBRARY。

### 调用关系四步链路

1. **DEC 声明 Library Class**：`[LibraryClasses] MyLib|Include/Library/MyLib.h`（声明接口）
2. **INF 实现 Library**：`LIBRARY_CLASS = MyLib`（实现）
3. **DSC 映射实现**：`[LibraryClasses] MyLib|MyPkg/Library/MyLib/MyLib.inf`（映射，支持覆盖）
4. **Driver INF 使用 Library**：`[LibraryClasses] MyLib`（只写 Class 名，Build Tool 自动查找）

> LIBRARY 是代码共享的核心机制：DEC 声明接口 → INF 实现 → DSC 映射 → 其他 Driver 引用。

## PCD Get & Set

PCD 生命周期：DEC 定义（默认值）→ INF 声明使用 → DSC 覆盖值 → 代码中 Get/Set。

| PCD 类型 | Get 接口 | Set 接口 | 修改时机 |
| --- | --- | --- | --- |
| FeatureFlag | FeaturePcdGet(X) | 只读 | 仅编译时 |
| FixedAtBuild | FixedPcdGetXxx(X) | 只读 | 仅编译时 |
| PatchableInModule | PatchPcdGetXxx(X) | PatchPcdSetXxx(X) | 编译后补丁 |
| Dynamic | PcdGetXxx(X) | PcdSetXxx(X) | 运行时 |
| DynamicEx | PcdGetEx(G,X) | PcdSetEx(G,X) | 运行时 |

命名规则：GetXX() 中 XX 为数据类型——Bool / Uint8 / Uint16 / Uint32 / Uint64 / Size / Pointer。FixedAtBuild / FeatureFlag 只能编译时读，不可写。

### 代码示例

```c
#include <Uefi.h>
#include <Library/PcdLib.h>

// 1. FeaturePcd — 布尔开关
if (FeaturePcdGet (PcdComponentNameDisable)) {
  DEBUG ((DEBUG_INFO, "Feature disabled!\n"));
}

// 2. FixedPcd — 编译时固定值
UINT64 FsbClock = FixedPcdGet64 (PcdFSBClock);

// 3. PatchPcd — 可补丁修改
UINTN PatchVal = PatchPcdGet32 (PcdSomeValue);

// 4. Dynamic Pcd — 运行时读写
UINT32 SerialBaud = PcdGet32 (PcdSerialBaudRate);
PcdSet32 (PcdSerialBaudRate, 115200);   // 写只能在 DXE 阶段

// 5. DynamicEx — 显式 TokenSpace
UINT32 Val = PcdGetEx32 (&gMyPkgTokenSpaceGuid, PcdMyCustomValue);

// 6. 字符串/字节数组
CHAR8 *Str  = PcdGetPtr (PcdSomeString);
```

PCD 使用前提：INF [Packages] 包含 PCD 定义所在的 DEC；INF 中声明使用的 PCD 段（[FixedPcd] 等）；代码包含 `<Library/PcdLib.h>`；DEC 中有对应 PCD 定义和默认值。

### 完整流程（四步）

1. **DEC 定义**：`[PcdsFixedAtBuild] gPkgTsGuid.PcdSerialBaud|115200|UINT32|0x00000001`
2. **INF 引用**：`[FixedPcd] gEfiMdePkgTsGuid.PcdSerialBaud`
3. **DSC 覆盖**：`[PcdsFixedAtBuild] gPkgTsGuid.PcdSerialBaud|921600`（优先级：DSC > INF > DEC）
4. **代码读写**：`UINT32 Baud = FixedPcdGet32 (PcdSerialBaud);`

常见错误：FixedAtBuild 用 PcdSet → 编译报错（只读）；INF 引用的 PCD 未在 DEC 定义 → Build 失败；PCD 段名必须匹配类型（[FixedPcd] ↔ PcdsFixedAtBuild）。

## INF 与 DEC 关系总结

三类资源的声明/消费方式：

| 资源 | DEC 侧 | INF 侧 |
| --- | --- | --- |
| GUID/Protocol/PPI | 定义 GUID 值 | `[Guids] gEfiXxxGuid` |
| Library Class | 声明接口 | `[LibraryClasses] MyLib` |
| PCD | 定义类型+值 | `[FixedPcd] Guid.PcdName` |

核心规则：
1. INF [Packages] 必须包含所有 PCD/GUID/Protocol 所在的 DEC
2. INF 中声明的 PCD 段必须与 DEC 定义的类型匹配
3. DSC 可以覆盖 DEC/INF 中定义的 PCD 值和 Library 映射
4. LIBRARY 链路：DEC 声明接口 → INF 实现 → DSC 映射 → 其他 INF 使用

## 常见构建错误速查

| 错误信息 | 原因 | 解决 |
| --- | --- | --- |
| "Guid not found in any DEC file" | [Guids] 引用了未定义的 GUID | 检查 [Packages] 是否包含对应 DEC；检查 GUID CName 拼写 |
| "No library instance found" | [LibraryClasses] 缺少映射 | DSC [LibraryClasses] 添加映射 |
| "PCD type mismatch" | INF 中 PCD 段与 DEC 类型不一致 | 确保 [FixedPcd] 对应 DEC 的 PcdsFixedAtBuild |
| "Undefined reference" | 链接错误，缺少 Library 实现 | 确认 [LibraryClasses] 已添加，DSC 中有对应映射 |
