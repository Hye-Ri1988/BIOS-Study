# PEI HOB（Hand-Off Block）

PEI 在启动早期跑在 CAR（Cache 当内存用）里，空间很紧，能发现多少硬件、内存布局长什么样，都会先记录在 HOB 中；等 DXE 起来，照着 HOB 去接管系统。

**为什么非要用 HOB？** PEI 和 DXE 跑在不同的内存空间，没法共享全局变量；CAR 资源又少，所以必须有一个标准化的、躺在连续内存里的数据结构来传话。HOB 就是规范规定的那个唯一传话机制。

## HOB 长什么样

整个 HOB List 是一段连续内存，里面一个接一个排着 HOB。每个 HOB 头 8 个字节：

```c
typedef struct {
  UINT16  HobType;    // 类型，2 字节
  UINT16  HobLength;  // 这个 HOB 总长，2 字节
  UINT32  Reserved;   // 保留，4 字节
} EFI_HOB_GENERIC_HEADER;
```

找下一个 HOB 的办法：当前地址 + HobLength。链表靠 Length 串起来，第一个永远是 PHIT HOB，最后一个类型必须是 END_OF_HOB_LIST（0xFFFF）。

**PHIT HOB** 是整个 HOB 的"目录入口"：记了启动模式（Boot Mode）、永久内存的基址和大小、HOB List 自己的起止指针。DXE 一上来先找到 PHIT，才能顺着 HOB list 读出来。

## PEI 这边怎么写

PEI Core 启动后第一件事建 PHIT HOB，一开始建在 CAR 里。等永久内存初始化完，把整张 HOB List 搬过去（**MigrateHobList**：分配新空间 → 逐字节拷贝 → 更新 PHIT 指针 → 更新 PEI Core 内部记录 → 回收 CAR）。

写新 HOB 用 `(*PeiServices)->CreateHob(...)`。底层逻辑：定位到当前 End 标记前面，检查空间够不够，不够就扩内存池，写好新 HOB 头部，再把 End 标记往后挪。只返回指针，具体数据由调用者填。

实际在 PEIM 里传自定义数据，一般直接调 `BuildGuidDataHob(GUID, Data, Size)`，一行搞定——HobLib 把创建和填数据打包好了。

```c
Status = (*PeiServices)->CreateHob(PeiServices,
    EFI_HOB_TYPE_MEMORY_ALLOCATION,
    sizeof(MY_EFI_HOB_TYPE), &Hob);  // 拿到 Hob 指针
if (EFI_ERROR(Status)) return Status;
Hob->Name = gMyPEIHobGUID;            // 写 GUID
(*PeiServices)->CopyMem(Hob->data, "HOB Data", 9);  // 写数据
```

## DXE 这边怎么读

DXE 是只读方。链路：PEI 把 HOB List 指针放进 PHIT HOB → DXE Core 启动读出来 → 各 DXE Driver 遍历。DXE 不准改、不准删 HOB，哪怕 ExitBootServices 之后 Runtime 驱动还可能来读。

```c
Hob.Raw = GetHobList();                       // 1. 拿到清单头
while ((Hob.Raw = GetNextHob(                 // 2. 按类型往下找
    EFI_HOB_TYPE_MEMORY_ALLOCATION, Hob.Raw)) != NULL) {
  if (CompareGuid(&gMyPEIHobGUID,             // 3. 比对 GUID
        &Hob.MemoryAllocation->AllocDescriptor.Name)) {
    MY_Hob = (MY_EFI_HOB_TYPE*)Hob.Raw;       // 4. 找到了，读数据
    return EFI_SUCCESS;
  }
  Hob.Raw = GET_NEXT_HOB(Hob);                // 步进
}
```

核心四步：GetHobList 拿头，GetNextHob 按类型筛，CompareGuid 对 GUID，命中就强转结构体读出来。

## 常见的几种 HOB 类型

| Type | 名称 | 作用 | 由谁建立 | |
| ------ | ------------------- | ------------------------ | ------------------- | --- |
| 0x0001 | PHIT HOB | 清单入口，记启动模式和内存信息 | PEI Core | 必需 |
| 0x0002 | Memory Allocation | 报 PEI 分配了哪些内存 | PEI Memory Services | 必需 |
| 0x0003 | Resource Descriptor | 报系统资源（MMIO / IO / 固件） | PEI Drivers | 必需 |
| 0x0004 | Firmware Volume | 固件卷在哪 | PEI Core | 必需 |
| 0x0005 | CPU HOB | CPU 地址位宽、核信息 | CPU PEIM | 必需 |
| 0x0006 | Memory Pool | 已弃用 | PEI Core | 可选 |
| 0x0007 | Capsule Volume | 胶囊更新卷 | Capsule PEIM | 条件 |
| 0x0008 | FV2 HOB | FV 扩展信息 | PEI Core | 条件 |
| 0x0009 | FV3 HOB | FV 认证信息 | PEI Core | 条件 |
| 0xFFFE | GUID Extension | 自定义数据，最灵活 | 任意 PEIM | 通用 |
| 0xFFFF | End of HOB List | 结束标记 | PEI Core | 必需 |

- **Memory Allocation 和 Resource Descriptor 是一对**。前者说"谁在用哪块内存"，后者说"物理地址空间里有什么"。DXE 拿这两样才能拼出完整物理内存视图，进而建 GCD
- **GUID Extension HOB（0xFFFE）**最灵活，想传什么自定义数据都行，靠 GUID 区分。EDKII 里很多信息都走它（性能数据、平台信息、SMM 保留内存、图形信息）
- **CPU HOB** 给地址位宽（如物理地址 64 位），DXE 多核服务靠它初始化
- **Boot Mode** 记在 PHIT 里。S3 唤醒时大部分硬件初始化可直接跳过——PEI 已把状态记在 HOB 上，DXE 直接读，省一遍重新探测硬件的时间

## HobLib 常用 API

- PEI / DXE 都能用（查）：`GetHobList()`、`GetFirstHob(TYPE)`、`GetNextHob(TYPE, Hob)`、`GetFirstGuidHob(GUID)`、`GetNextGuidHob(GUID, Hob)`
- 只在 PEI 用（建）：`BuildGuidHob`、`BuildGuidDataHob`、`BuildCpuHob`、`BuildResourceDescriptorHob`、`BuildMemoryAllocationHob`、`BuildFvHob`

DXE 只有"查"的接口，PEI 才有"建"的接口——跟"PEI 写、DXE 读"的原则对应。
