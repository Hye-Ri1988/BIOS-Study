# PCIe：串行点对点总线、4KB 配置空间与 BIOS 枚举实践

PCI Express（PCIe）是 PCI 的继任者：物理层从 32/64 位并行共享总线换成高速串行差分点对点链路，但软件编程模型（配置空间读写、BDF 编址、BAR 分配、ClassCode 匹配）原样保留，OS 和驱动几乎无感迁移。对固件工程师而言，PCIe 的核心工作分三块：**枚举**（按 BDF 扫出所有设备）、**资源分配**（给 BAR 和桥窗口安放 MMIO/I/O 地址）、**能力配置**（按 Capability 结构配置链路、中断、电源和错误特性）。

> PCI 配置空间相当于 MCU 外设寄存器组——CF8/CFC 端口是"寄存器间接访问"（先写地址寄存器再读数据寄存器，两步非原子）；PCIe 的 ECAM 相当于把整个外设寄存器组直接映射进地址空间，一条内存读写指令完成访问。枚举过程则像遍历 I2C 总线上所有从机地址：写地址、读回应（VendorID != 0xFFFF），无回应就跳过。

---

## 一、概述：从并行 PCI 到串行 PCIe

PCI 1992 年发布，32/64 位并行总线、共享仲裁，33/66 MHz 时钟，64-bit@66MHz 最高 533 MB/s。所有设备共享同一总线带宽，信号线约 120 根，布线复杂。PCI 3.0（2004）是并行 PCI 的最终版本。

PCIe 2003 年发布，高速串行差分点对点，每 Lane 双向独立，支持 x1/x2/x4/x8/x16 链路聚合，全双工、基于数据包的事务传输。Gen5 单 Lane 32 GT/s，x16 双向约 126 GB/s。

| 特性 | PCI（并行） | PCIe（串行） |
| --- | --- | --- |
| 物理信号 | 共享并行总线（AD[31:0]、C/BE# 等） | 差分串行对（TX+/TX-、RX+/RX-） |
| 连接方式 | 多点共享（Multi-drop） | 点对点（Point-to-Point） |
| 配置空间 | 256 B（CF8h/CFCh 端口） | 4 KB（ECAM，MMIO 映射） |
| 事务模型 | 总线仲裁 + 读写周期 | 数据包 TLP/DLLP |
| 带宽扩展 | 固定（133/533 MB/s） | Lane 聚合（x1~x16） |
| 电源管理 | D0~D3 | D0~D3 + ASPM L0s/L1 |
| 热插拔 | 有限支持 | 原生支持（Attention Button / Surprise） |
| 错误报告 | SERR#/PERR# 信号线 | AER 扩展能力结构 |
| 中断 | INTA#~INTD# 线中断 | MSI/MSI-X 消息中断 |

演进路线：PCI 1.0（1992, 33MHz）→ PCI 2.2（1998, 66MHz）→ PCI 3.0（2004, 最终版）→ PCIe 1.0（2003, 2.5 GT/s）→ PCIe 3.0（2010, 8 GT/s）→ PCIe 5.0（2019, 32 GT/s）。

> [!tip]
> 区分设备是 PCI 还是 PCIe，软件层面看 Capability ID：PCIe 设备在 0x34 指向的能力链表中**必有 Cap ID = 0x10（PCI Express Capability）**，PCI 设备没有。这是 EDK2 `PciExtIsPciExpresss()` 的判断依据。

## 二、PCI 总线架构与 BDF 编址

层次结构：Host Bridge 连接 CPU 与 Bus 0；PCI-to-PCI Bridge（P2P）扩展下级总线；每条总线最多 32 个 Device（0~31），每 Device 最多 8 个 Function（0~7）；系统最多 256 条总线（0~255）。

编址方式 **BDF**（Bus:Device.Function）：例 `00:1F.2` = Bus 0、Device 31、Function 2。

```c
// 枚举伪代码：遍历全部 BDF，读 VendorID 判存在性
for (Bus = 0; Bus <= 255; Bus++)
  for (Device = 0; Device <= 31; Device++)
    for (Func = 0; Func <= 7; Func++) {
      VendorId = PciRead16(ECAM(Bus, Device, Func, 0x00));
      if (VendorId == 0xFFFF) {           // 无设备
        if (Func == 0) break;             // Func0 都不存在 → 整 Device 跳过
        continue;
      }
      HdrType = PciRead8(ECAM(Bus, Device, Func, 0x0E));
      if ((HdrType & 0x7F) == 0x01) {     // P2P Bridge：递归枚举 Secondary Bus
        SecBus = PciRead8(ECAM(Bus, Device, Func, 0x19));
        EnumerateBus(SecBus);
      }
      AssignBarResources(Bus, Device, Func);
      if (Func == 0 && !(HdrType & 0x80)) break;  // 非多功能设备
    }
```

> [!note]
> VendorID 全 0xFFFF 表示该 BDF 槽位无设备（MCU 类比：I2C 从机不应答返回 NACK）。HeaderType bit7（0x80）置位表示多功能设备；bit6:0 才是 0=Device / 1=Bridge。

## 三、PCI 配置空间：256B 头结构

256 字节配置空间布局（Type 0/1 共用前 64B 设备无关区）：

| 偏移 | Header Type 0（Device） | Header Type 1（Bridge） | 说明 |
| --- | --- | --- | --- |
| 0x00-0x0F | VendorID/DeviceID/Command/Status/RevisionID/ClassCode/CacheLineSize/LatencyTimer/HeaderType/BIST | 同左 | 设备无关区 |
| 0x10-0x27 | BAR[0]~BAR[5]（6 个） | BAR[0]~BAR[1]（2 个） | 基地址寄存器 |
| 0x18-0x1B | CIS Pointer | PrimaryBus/SecondaryBus/SubBus/LatTimer | 桥接总线编号 |
| 0x1C-0x1D | — | I/O Base / I/O Limit | 桥接 I/O 窗口 |
| 0x20-0x23 | — | Memory Base / Memory Limit | 桥接内存窗口 |
| 0x30-0x33 | Expansion ROM BAR | Expansion ROM BAR | Option ROM 地址 |
| 0x34 | Capability Pointer | Capability Pointer | 能力链表头 |
| 0x3C-0x3D | Interrupt Line/Pin | Interrupt Line/Pin | 中断路由 |

```c
// MdePkg/Include/IndustryStandard/Pci22.h —— PCI_DEVICE_INDEPENDENT_REGION
typedef struct {
  UINT16  VendorId;        // 0x00
  UINT16  DeviceId;        // 0x02
  UINT16  Command;         // 0x04
  UINT16  Status;          // 0x06
  UINT8   RevisionID;      // 0x08
  UINT8   ClassCode[3];    // 0x09 BCC/SCC/PI
  UINT8   CacheLineSize;   // 0x0C
  UINT8   LatencyTimer;    // 0x0D
  UINT8   HeaderType;      // 0x0E
  UINT8   BIST;            // 0x0F
} PCI_DEVICE_INDEPENDENT_REGION;
```

常用 Class Code（BCC/SCC/PI 三字节，驱动匹配依据）：0x01 Mass Storage（SATA/NVMe/AHCI/RAID）、0x02 Network、0x03 Display、0x06/0x00 Host Bridge、0x06/0x04 PCI-PCI Bridge。

**BAR 格式**：bit0 = 0 表示 Memory 空间、=1 表示 I/O 空间；Memory BAR 的 bit[2:1]：00=32-bit、10=64-bit（低 BAR 的 bit[2:1]=10 时占用相邻两个 BAR 组成 64 位地址）。BAR 位宽探测：写全 1 再读回，低位置零后的值即 BAR 大小。

**Command 寄存器关键位**：bit0 I/O Space Enable、bit1 Memory Space Enable、bit2 Bus Master Enable。设备被发现后默认 Decode 关闭，资源分配完成后才置位使能。

> MCU 类比：BAR 类似 MCU 外设的基地址寄存器，探测"需要多大地址窗口"的方法和 ARM 下读外设寄存器"保留位为 0"的用法同理——写 0xFFFFFFFF 读回，剩下的"1"位就是可编程地址位。

## 四、PCIe 体系架构：三层模型与 TLP

| 层                      | 职责                 | 关键机制                                              |
| ---------------------- | ------------------ | ------------------------------------------------- |
| Transaction Layer（事务层） | TLP 数据包读写/完成/消息    | MRd/MWr、IORd/IOWr、CfgRd0/CfgWr0、Cpl/CplD、Msg/MsgD |
| Data Link Layer（数据链路层） | DLLP 流控、ACK/NAK 重传 | 保证 TLP 可靠传输                                       |
| Physical Layer（物理层）    | LTSSM 链路训练、编解码     | 8b/10b（Gen1/2）或 128b/130b（Gen3+）                  |

各代速率（x1 单向带宽按编码效率折算）：

| 代次 | 传输速率 | 编码 | x1 单向带宽 | x16 双向带宽 |
| --- | --- | --- | --- | --- |
| Gen 1 | 2.5 GT/s | 8b/10b | ~250 MB/s | ~8 GB/s |
| Gen 2 | 5.0 GT/s | 8b/10b | ~500 MB/s | ~16 GB/s |
| Gen 3 | 8.0 GT/s | 128b/130b | ~985 MB/s | ~31.5 GB/s |
| Gen 4 | 16.0 GT/s | 128b/130b | ~1.97 GB/s | ~63 GB/s |
| Gen 5 | 32.0 GT/s | 128b/130b | ~3.94 GB/s | ~126 GB/s |

TLP 关键类型：`MRd/MWr`（Memory 读写）、`IORd/IOWr`（I/O 读写）、`CfgRd0/CfgWr0`（配置读写，0=Bus0 语义）、`Cpl/CplD`（完成/带数据完成，读请求必须回复）、`Msg/MsgD`（消息，如 INTx 虚拟化、PME、错误上报）。

## 五、ECAM 配置空间：4KB MMIO 映射与 MCFG 表

### 5.1 从 CF8/CFCh 到 ECAM

Legacy PCI 用 I/O 端口间接访问：向 `0xCF8`（CONFIG_ADDRESS）写 BDF+偏移，再从 `0xCFC`（CONFIG_DATA）读写数据。两步访问非原子，多线程下可能互相踩踏；且寄存器偏移字段只有 8 位，**最多访问 256B**，无法触及 PCIe 的扩展空间。

ECAM（Enhanced Configuration Access Mechanism）把每个 Function 的 4KB 配置空间平铺映射进内存地址空间，一次普通内存读写即完成一次配置访问，原子且多线程安全。整个映射区最多 256MB（256 总线 × 32 设备 × 8 功能 × 4KB）。

```
ECAM 地址 = ECAM_BASE + (Bus << 20) | (Device << 15) | (Function << 12) | Offset
             [63:28]     [27:20]        [19:15]          [14:12]          [11:0]
```

```c
// MdePkg/Include/IndustryStandard/PciExpress21.h —— ECAM 地址编码宏
#define PCI_ECAM_ADDRESS(Bus, Device, Function, Offset) \
  (((Offset) & 0xfff)                      \
   | (((Function) & 0x07) << 12)           \
   | (((Device)   & 0x1f) << 15)           \
   | (((Bus)      & 0xff) << 20))

// 读取 Bus0/Dev0/Func0 的 VendorID
UINT16 VendorId = MmioRead16(PcieBase + 0x000);
```

4KB 空间布局：`0x000-0x03F` PCI 兼容头（64B）、`0x040-0x0FF` PCI Capability 链表、`0x100-0x1FF` PCIe Extended Capability（可选）、`0x200-0xFFF` 保留/厂商自定义。Extended Capability Header 格式：ID[15:0] + Version[19:16] + NextOffset[31:20]。

### 5.2 MCFG 表：BIOS 与 OS 的交接

ECAM 基址不是 OS 自己探测的，而是固件通过 **ACPI MCFG 表**（Memory Mapped Configuration Space Base Address Description Table，PCI Firmware Spec 定义）告知 OS。固件在启动时配置好地址解码，OS 读 MCFG 拿基址后即可用普通内存指令访问全部 4KB 配置空间。

```c
// 工程对照：AmiModulePkg/PCI/PciHostBridge.c:1639
// 平台 ECAM 基址存在 PCD 中，Host Bridge 驱动把它同步进 ACPI DSDT 的 PEBS 对象
Status = UpdateAslNameObject(dsdt, (UINT8*)"PEBS", PcdGet64(PcdPciExpressBaseAddress));
```

> [!note]
> Linux 下可用 `cat /proc/iomem | grep MMCONFIG` 查看 ECAM 基址，例如 `f8000000-fbffffff : PCI MMCONFIG 0000 [bus 00-3f]`——基址 0xF8000000，映射了 Bus 0~3F。OS 严格依赖 MCFG 提供的地址范围，不允许内核擅自修改基址（地址解码由固件预配置）。

> [!warning]
> BIOS 阶段**禁止用 CF8/CFC 访问 PCIe 扩展空间（>0xFF）**。工程实现（AmiModulePkg/PCI/PciBus.c:1026）对 PCIe 设备允许偏移到 0xFFF，非 PCIe 设备限制在 0xFF，并通过 `ExtendedRegister` 位编码高偏移。

## 六、Capability 结构：PCI Cap 与 PCIe Extended Cap

### 6.1 PCI Capability 链表（0x34 起始）

每个 Capability：`[CapID:1B][NextPtr:1B][Data:...]`，NextPtr=0 表示链表尾。常见 ID：0x01 Power Management、0x05 MSI、0x10 PCI Express、0x11 MSI-X。

PCIe Capability（Cap ID 0x10）完整结构（PciExpress21.h）：

```c
typedef struct {
  EFI_PCI_CAPABILITY_HDR           Hdr;        // ID + Next
  PCI_REG_PCIE_CAPABILITY          Capability; // Device/Port Type
  PCI_REG_PCIE_DEVICE_CAPABILITY   DevCap;     // MaxPayload、FLR...
  PCI_REG_PCIE_DEVICE_CONTROL      DevCtrl;    // MPS、MRRS、NoSnoop
  PCI_REG_PCIE_DEVICE_STATUS       DevSta;
  PCI_REG_PCIE_LINK_CAPABILITY     LnkCap;     // Speed、Width、ASPM
  PCI_REG_PCIE_LINK_CONTROL        LnkCtrl;    // ASPM Control
  PCI_REG_PCIE_LINK_STATUS         LnkSta;     // Negotiated Speed/Width
  PCI_REG_PCIE_SLOT_CAPABILITY     SlotCap;    // HotPlug、Power Limit
  PCI_REG_PCIE_SLOT_CONTROL        SlotCtrl;
  PCI_REG_PCIE_SLOT_STATUS         SlotSta;
  PCI_REG_PCIE_ROOT_CONTROL        RootCtrl;   // Root Port Only
  ...
  PCI_REG_PCIE_DEVICE_CAPABILITY2  DevCap2;
  PCI_REG_PCIE_LINK_CAPABILITY2    LnkCap2;
} PCI_CAPABILITY_PCIEXP;
```

关键寄存器与 BIOS 用途：

| 寄存器 | 关键字段 | 含义 | BIOS 用途 |
| --- | --- | --- | --- |
| Device Capability | MaxPayloadSize[2:0] | 最大 TLP Payload 128B~4096B | 资源分配参考 |
| Device Control | MPS/MRRS | 软件可配的 MaxPayloadSize / MaxReadReqSize | 性能调优 |
| Link Capability | MaxLinkSpeed[3:0]/MaxLinkWidth[5:0] | 链路最大速率和宽度 | 识别设备能力 |
| Link Status | CurrentLinkSpeed/NegotiatedLinkWidth | 当前实际协商速率/宽度 | 诊断链路状态 |
| Slot Capability | HotPlugCapable/HotPlugSurprise | 热插拔支持标志 | HotPlug 初始化 |
| Device Capability2 | CompletionTimeoutRanges/ARI | 完成超时范围、ARI 转发 | 高级功能配置 |

Device/Port Type（Capability 寄存器 Bits[7:4]）：0x0 Endpoint、0x1 Legacy Endpoint、0x4 Root Port、0x5 Upstream Port、0x6 Downstream Port、0x7 PCIe-to-PCI Bridge、0x8 PCI-to-PCIe Bridge、0x9 RCiEP、0xA RC Event Collector。

### 6.2 PCIe Extended Capability（偏移 0x100 起）

常用 Extended Cap ID：0x0001 AER（高级错误报告）、0x000E ARI、0x0010 SR-IOV、0x0015 Resizable BAR、0x0018 LTR（延迟容忍报告）。

```c
// 工程对照：AMI_PCI_EXT_PROTOCOL.PciExtIsPciExpresss()
// AmiModulePkg/PCI/PciBus.c:11802 → 内部调用 PcieCheckPcieCompatible()
// 实现本质：在设备 Capability 链表中查找 Cap ID 0x10（PCI Express Capability）
```

> [!tip]
> 判断设备是否 PCIe 的可靠方法不是看链路速率，而是查 Cap ID 0x10。老式 PCI-X 设备有 0x07（PCI-X）Capability，与 PCIe 区分开。

## 七、LTSSM 链路训练与速度协商

LTSSM（Link Training and Status State Machine）位于物理层逻辑子层，管理链路从上电到稳定通信的全过程：

```
Detect → Polling → Configuration → L0 ──→ L0s/L1/L2（省电）
  ↑          ↑                        │
  └──────────┴────────────←───────────┘
  （故障/重训练）                    Recovery →（速率切换/均衡）→ L0
                                    Hot Reset / Disabled / Loopback（调试态）
```

| 状态 | 作用 |
| --- | --- |
| Detect | 检测对端（Receiver 阻抗），Reset 后初始态 |
| Polling | Lane 极性检测、速率能力协商（TS1/TS2 有序集） |
| Configuration | Lane 编号协商，确定 x1/x2/x4/x8/x16 |
| L0 | 全速运行态，正常 TLP/DLLP 传输 |
| L0s | 短省电态，单向收发器关闭，ns 级唤醒 |
| L1 | 深省电态，整个链路关闭，μs 级唤醒 |
| L2/L3 | 辅助断电，需唤醒信号 |
| Recovery | 重训练核心状态：速率切换、错误恢复、均衡 |
| Hot Reset/Disabled/Loopback | 热复位 / 软件禁用 / 环回测试 |

**Recovery 是链路容错与升级的关键**：进入场景包括信号质量劣化（误码率超标）、从 L0s/L1 唤醒、速率升级（Gen1→Gen3/4/5）、软件主动重训练。子状态流程：`Recovery.RcvrLock`（重发 TS1 恢复 Bit/Block Lock，置 Speed Change 标志）→ `Recovery.RcvrCfg`（协商目标速率）→ `Recovery.Speed`（切换速率，发 EIEOS）→ `Recovery.Equalization`（Gen3+ 专属）→ `Recovery.Idle`（回 L0）。恢复失败超时会退回 Detect 全流程重训。

**Equalization（Gen3+ 必备，补偿 PCB 高频损耗）**，四阶段：

- Phase 0：DSP 通过 TS2 向 USP 每 Lane 发送所需 Tx Preset 值，USP 切至 Gen3 速率并回 TS1
- Phase 1：重复发送 TS1 确保 Preset 正确接收，BER ≤ 1E-4 后进入 Phase 2
- Phase 2：DSP 调整 USP 的 Preset 至最优（BER ≤ 1E-12）
- Phase 3：USP 调整 DSP 的 Preset（BER ≤ 1E-12）

Gen3/Gen4 有 11 个 Preset（Preset0~10，预过冲+去加重组合）。均衡失败且重试仍失败则降速。Gen5 起支持 Equalization bypass（跳过中间速率直接切最高速）与 No equalization needed 模式。

```c
// PciExpress21.h —— Link Capability / Link Status 位域
typedef union {
  struct {
    UINT32  MaxLinkSpeed     : 4;  // 1=2.5GT, 2=5GT, 3=8GT, 4=16GT, 5=32GT
    UINT32  MaxLinkWidth     : 6;  // x1,x2,x4,x8,x16
    UINT32  Aspm             : 2;
    UINT32  L0sExitLatency   : 3;
    UINT32  L1ExitLatency    : 3;
  } Bits;
  UINT32 Uint32;
} PCI_REG_PCIE_LINK_CAPABILITY;
```

> [!warning]
> 90% 的 PCIe 链路调试问题表现为 LTSSM 卡在某状态：卡 Polling 多为信号质量/极性问题，卡 Configuration 多为 Lane 分配协商失败，卡 Recovery 多为均衡失败。诊断时先看 Link Status 的 NegotiatedLinkWidth 与 CurrentLinkSpeed 是否达到预期（UEFI Shell `pci` 命令可查）。

## 八、BIOS 中的 PCIe 枚举与资源分配

### 8.1 总体流程

```
SEC/PEI: FSP 初始化 Root Bridge（ECAM 基址、Bus 范围）
DXE:     PciHostBridge 驱动 → 安装 RootBridgeIo 协议
         PciBus 驱动枚举 → 扫描 BDF 读 VendorID
         BAR 分配 → 汇总需求、申请窗口、写入 BAR、配 Bridge Base/Limit
         Driver Binding → 匹配驱动、安装 PciIo 协议
```

EDK2 关键协议与库：`EFI_PCI_ROOT_BRIDGE_IO_PROTOCOL`（Root Bridge I/O 操作）、`EFI_PCI_HOST_BRIDGE_RESOURCE_ALLOCATION_PROTOCOL`（资源分配）、`EFI_PCI_IO_PROTOCOL`（每个 PCI 设备的 I/O 接口，含配置空间读写、BAR、DMA Map、属性设置）。

### 8.3 BAR 分配与 Bridge 窗口

PciHostBridge 驱动核心任务：扫描汇总 BAR 需求 → 按 Bus/IO/Mem/Prefetch 分类 → 向 Host Bridge 申请资源窗口 → 写入 BAR 并置位 Memory/IO Space Enable → 配置 Bridge Base/Limit。

P2P Bridge（Type 1）窗口寄存器（Pci22.h `PCI_BRIDGE_CONTROL_REGISTER` 节选）：

```c
UINT8   PrimaryBus;            // 0x18 主总线号
UINT8   SecondaryBus;          // 0x19 从总线号
UINT8   SubordinateBus;        // 0x1A 最大下级总线号
UINT8   IoBase;                // 0x1C  I/O 窗口基址
UINT8   IoLimit;               // 0x1D  I/O 窗口限制
UINT16  MemoryBase;            // 0x20  Memory 窗口基址
UINT16  MemoryLimit;           // 0x22  Memory 窗口限制
UINT16  PrefetchableMemoryBase;    // 0x24
UINT16  PrefetchableMemoryLimit;   // 0x26
UINT32  PrefetchableBaseUpper32;   // 0x28 64-bit 高 32 位
UINT32  PrefetchableLimitUpper32;  // 0x2C
UINT16  IoBaseUpper16;             // 0x30 I/O 高 16 位
UINT16  IoLimitUpper16;
```

窗口分配原则：Memory 1MB 对齐、I/O 4KB 对齐；Prefetchable Memory 可 64-bit 编址，适合大 BAR 设备（GPU）。Bus 号级联示例：Bus0 Root（Primary=0）→ Bus1 Root Port（Sec=1, Sub=3）→ Bus2 Switch USP（Sec=2, Sub=3）→ Bus3 Switch DSP（Sec=3, Sub=3）。

```c
// 工程对照：AmiModulePkg/PCI/PciBus.c
// PciEnumerateAll()  @8897 —— 全总线枚举入口（PciBusStart 中调用）
// StartPciDevices()  @11132 —— 启动指定设备，安装 PciIo
// PciExtIsPciExpresss() @11802 —— 查 Cap ID 0x10 判断 PCIe
// Bridge SecondaryBus 写入 @2971/3137/3231 —— Res[rtBus].Base → 0x19
// 配置空间访问限制   @1026 —— PCIe 设备 0xFFF / 传统 PCI 0xFF
```

> [!note]
> 资源分配冲突是 BIOS 调试常见问题：MMIO 不足时设备 BAR 分配失败导致设备不可用。对策包括打开 Setup 的 **Above 4G Decoding**（把大 BAR 放到 4G 以上）或 **Resizable BAR**（Cap ID 0x0015，允许按设备最大需求动态扩展 BAR 尺寸）。Resizable BAR 在 EDK2 中由 2021 年补丁引入（`PciProgramResizableBar` + `PcdPcieResizableBarSupport`），本工程依赖 AMI 自有实现。

## 九、中断：INTx → MSI/MSI-X

| 特性 | INTx（Legacy） | MSI | MSI-X |
| --- | --- | --- | --- |
| Cap ID | N/A（0x3C 寄存器） | 0x05 | 0x11 |
| 最大向量数 | 4（共享） | 32 | 2048 |
| 触发方式 | 电平/边沿信号 | Memory Write TLP | Memory Write TLP |
| 共享冲突 | 是 | 否 | 否 |
| 64-bit 地址 | N/A | 可选 | 支持 |
| Per-Vector Mask | 否 | 可选 | 支持 |

INTx 时代 BIOS 负责 PIRQ 中断路由表（ICH/PCH 的 PIRQ 寄存器映射），OS 再按 ACPI `_PRT` 表把 PCI 设备中断连接到 PIC/APIC 输入。MSI/MSI-X 无需物理中断线，设备直接向指定 MMIO 地址（Message Address/Data）发起 Memory Write TLP 触发中断，无共享冲突、可独立分配 CPU 目标。

> [!tip]
> BIOS 阶段需检测设备 MSI/MSI-X Capability，并在 ACPI 表中正确描述中断控制器（x2APIC/IOAPIC），OS 才能正确配置 MSI 路由。MSI-X 每向量独立 Table（含 Message Address、Message Data、Vector Control），支持逐向量 Mask，是高吞吐设备（NVMe、网卡）首选。详见 [[ACPI]] 与 [[RunTime Services]] 笔记中的中断模型。

## 十、电源管理与错误处理：ASPM 与 AER

### 10.1 D 状态 vs ASPM

| 状态 | 类型 | 触发条件 | 唤醒延迟 | 功耗节省 |
| --- | --- | --- | --- | --- |
| D0 | 设备全功率 | 正常工作 | — | 100% |
| D1/D2 | 设备省电 | SW 控制 | ms 级 | ~30-50% |
| D3hot | 设备待机 | SW 控制 | ms~s 级 | ~90% |
| D3cold | 辅助断电 | 系统控制 | 需复位 | ~100% |
| L0s | ASPM 链路 | HW 自动 | ns 级 | ~25% |
| L1 | ASPM 链路 | HW 自动 | μs 级 | ~60-90% |

D 状态是**设备级**（PCI-PM Capability，软件控制）；L0s/L1 是**链路级**（ASPM，硬件自动）。ASPM 配置规则：读两端（USP+DSP）LnkCap.ASPM 能力取交集，写入 LnkCtrl.AspmControl（00b=Disable、01b=L0s、10b=L1、11b=L0s+L1）。

```c
// PciExpress21.h —— Link Control ASPM 控制位
UINT16  AspmControl   : 2;   // [1:0]
UINT16  LinkDisable   : 1;
UINT16  RetrainLink   : 1;   // 触发链路重训练
UINT16  CommonClockConfig: 1;
```

> [!warning]
> ASPM 设置不当会导致设备性能下降或链路不稳定。BIOS 通常通过 PCD 控制 ASPM 策略；GPU/NVMe 等高性能设备或链路裕量不足的场景常需禁用 ASPM。工程中 AMI 通过 SDL（Static Device Library）按设备配置 Pcie1Settings（见 PciBus.c:4397 的 `AmiPciGetPcie1SetupData`/`gPciDefaultSetup->Pcie1Settings`）。

### 10.2 AER 错误处理（Extended Cap ID 0x0001）

三类错误：

- **Correctable（CE）**：Bad TLP、Bad DLLP、Receiver Error —— 硬件自动纠正，记录不中断
- **Non-Fatal（NFE）**：Poisoned TLP、Completion Timeout、UR（Unsupported Request）—— 影响特定事务，设备仍工作
- **Fatal（FE）**：DLLP Protocol Error、Flow Control Error —— 链路不可信，需复位链路

```c
// PciExpress21.h —— PCI_EXPRESS_REG_UNCORRECTABLE_ERROR 位域（节选）
UINT32  DataLinkProtocolError   : 1;  // Fatal
UINT32  PoisonedTlp             : 1;  // Non-Fatal
UINT32  FlowControlProtocolError: 1;  // Fatal
UINT32  CompletionTimeout       : 1;  // Non-Fatal
UINT32  MalformedTlp            : 1;  // Fatal
UINT32  UnsupportedRequestError : 1;  // Non-Fatal
```

处理流程：硬件检测设 Status → Root Port 收集 Error Message → OS/BIOS 读 AER Status 分类处理 → CE 清标志、FE 复位链路。BIOS POST 阶段只做基础检测和日志记录，完整 AER 处理由 OS（如 Linux AER driver）负责；BIOS 需正确配置 Root Port 的 Error Reporting 使能位（Uncorrectable/MCorrectable Error Mask & Severity），确保 OS 能收到错误中断。

## 十一、SR-IOV：单根 I/O 虚拟化

Extended Cap ID 0x10。一个物理设备（PF, Physical Function）虚拟出多个轻量级虚拟功能（VF, Virtual Function），每个 VF 拥有独立配置空间、BAR、中断向量，可直通给 VM。

```c
// PciExpress21.h —— SR_IOV_CAPABILITY_REGISTER（节选）
UINT16  InitialVFs;       // 初始 VF 数量
UINT16  TotalVFs;         // 最大 VF 数量
UINT16  NumVFs;           // 当前活跃 VF 数量
UINT16  FirstVFOffset;    // 第一个 VF 的 RID 偏移
UINT16  VFStride;         // VF 之间的 RID 步长
UINT16  VFDeviceID;       // VF 的 Device ID
UINT32  VFBar[6];         // VF BAR 寄存器
```

BIOS 初始化流程：读取 Ext Cap 找 ID=0x10 → 设置 NumVFs、分配 VF BAR → 置 Control.VF Enable → 为每个 VF 分配 Bus:Dev:Func（BDF 编排）。

> [!note]
> SR-IOV 是服务器/工作站关键特性。BIOS 需在 Setup 提供 VF 数量配置选项，并保证 VF BAR 分配足够 MMIO 资源（VF 数量 × 每 VF BAR 大小）。AMI 平台由 `AmiSriovLib` 提供支持。VF 的 BDF 编排遵循 FirstVFOffset + n×VFStride 规则，Bus 号可能超出当前 Bus 范围，需预留（常配合 ARI 使用）。

## 十二、总结：BIOS 实践要点

1. **枚举**：遍历 BDF 读 VendorID（0xFFFF 判空），HeaderType bit7 判多功能，Type 1 递归 Secondary Bus
2. **配置空间访问**：PCIe 用 ECAM（MMIO），基址来自 PCD/MCFG；扩展空间（>0xFF）只能走 ECAM
3. **资源分配**：先汇总 BAR 需求再统一分配，Memory 1MB/I/O 4KB 对齐，Bridge 窗口 Base/Limit 覆盖子设备
4. **设备识别**：Cap ID 0x10 判 PCIe；Device/Port Type 区分 Endpoint/Root Port/Switch；Class Code 匹配驱动
5. **链路诊断**：看 Link Status 的 CurrentLinkSpeed/NegotiatedLinkWidth；LTSSM 卡状态定位信号/协商/均衡问题
6. **高级特性**：ASPM 按设备策略配置（PCD/SDL 控制）；AER 使能 Root Port 错误上报；SR-IOV 分配 VF BAR 与 BDF；MSI-X 优先于 INTx
7. **资源不足对策**：Above 4G Decoding、Resizable BAR（Cap 0x0015）
