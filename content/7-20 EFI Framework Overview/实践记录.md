# 今日实践练习：MTL 平台串口日志阶段分界 + ROM 拆解

## 练习 1：阅读 MTL 平台串口日志，标注启动阶段关键分界线

| 阶段 | 日志行号 | 关键日志内容 |
| ------------------- | --------- | ------ |
| SEC起点 | **2** | `FSP-T: CAR Init` |
| PEI Entry | **22** | `PeiCore.Entry(FFF889FE)` |
| MRC 内存训练 | **2362** → **2961** | `[InstallMrcCallback] MRC Entry...` → `MemoryInit Complete.` |
| PEI Re-Entry (DRAM) | **3071** | `Install PPI: EfiPeiMemoryDiscovered` |
| EndOfPei | **22577** | `Install PPI: EfiEndOfPeiSignal` |
| DXE Entry | **23113** | `[DxeIpl]: DXE-Core.Entry(61164C70)` |
| EndOfDxe | **30283** | `[Bds]: BDS.SignalEndOfDxe(580F37DC)` |
| BDS Handoff | **31976** | `[Bds]: BDS.HandoffToTse(580F4B30)` |

### 阶段边界解读

**1. SEC 起点 — 行 2: `FSP-T: CAR Init`**

UEFI PI 规范定义启动流程从 SEC 开始。Intel FSP 架构下 SEC 由 FSP-T 承担，`FSP-T: CAR Init` 是 FSP-T 入口：
- CPU 刚从 reset vector 跳转过来，开始 Cache-As-RAM (CAR) 初始化
- 行 7 `SecStartup()` 确认 TempRAM 建立 (Base=0xFEF00000, Size=0xFFF00)
- 行 38 `FPDT: SEC Performance Hob ResetEnd` 记录 SEC 性能数据结束，是 SEC 收尾标志

**2. PEI Entry — 行 22: `PeiCore.Entry(FFF889FE)`**

PEI Foundation 入口。SEC 找到 PEI Core 入口地址（行 19 `PeiCoreEntryPoint: 0xFFF888A0`）后跳转过来。行 39 `DiscoverPeimsAndOrderWithApriori(): Found 0x2E PEI FFS files` 确认 PEI Dispatcher 开始调度。

**3. MRC 内存训练 — 行 2362 → 2961**

- 行 2362 `[InstallMrcCallback] MRC Entry...`：平台显式声明的 MRC 回调入口，随后触发 `[PeimMemoryInit]` (行 2367)
- 行 2451 `MRC Start Memory Configuration`：训练正式开始，后续 `Fast boot permitted` → `Pre-Training` → `JEDEC RESET` → `Margin Limit Check` 逐步骤完成
- 行 2961 `MemoryInit Complete.`：MRC 显式结束。行 2972 `POSTCODE = <0000D055>` (0x55 = PI 规范 "Memory Init Complete")，行 2962 `Install PPI: AmiPeiEndOfMemDetectGuid`

**4. PEI Re-Entry (DRAM) — 行 3071: `Install PPI: EfiPeiMemoryDiscovered`**

PEI 从 Pre-Memory（栈在 Cache/TempRAM）切换到 Post-Memory（栈/堆在 DRAM）的分界点：
- 行 3072-3096 大量 PEIM 的 Notify 回调被触发
- 行 3085 `MtlBoardInitAfterMemoryInit` 显式标明 "After Memory"
- 行 2976-2980 TempRAM 使用统计 (stack 241040 / heap 212464 bytes) 说明迁移完成
- 后续行 3619 `FspsWrapperPeim.Entry` (FSP-S Wrapper) → 行 15770 `SiInitFsp.Entry` (FSP Silicon Init)

**5. EndOfPei — 行 22577: `Install PPI: EfiEndOfPeiSignal`**

PI 规范中 PEI 阶段的正式终结信号：
- 行 22570 `DxeIpl Entry` 作为 DXE IPL 被加载执行
- 行 22577 `EfiEndOfPeiSignal` — 此后 PEIM 不能再加载
- 行 22578-23111 大量 EndOfPei 回调 (VT-d, USB4, TCSS 等做交接清理)
- 行 23112 `[DxeIpl]: HandOffToDxeCore()` — PEI→DXE 移交完成

**6. DXE Entry — 行 23113: `DXE-Core.Entry(61164C70)`**

DXE Core 入口点 (`DxeMain()`)：
- 行 23114 `CoreInitializeMemoryServices` — 建立 DXE 内存服务
- 行 23128 `DxeMain: MemoryBaseAddress=0x100000 MemoryLength=0x5CB97000` — ≈1.45GB 可用内存
- 行 24502 `Bds.Entry` — BDS 架构协议被安装

**7. EndOfDxe — 行 30283: `BDS.SignalEndOfDxe`**

DXE 安全边界锁定：
- 行 30284 `POSTCODE = <00000091>` (0x91 = PI 规范 "EndOfDxe")
- 行 30570 `SmmEndOfDxeHandler` → 行 30571 `EfiSmmEndOfDxe 0` — SMM 侧也锁定
- 此后 Flash 写保护、Secure Boot 策略生效，不再允许加载新 DXE 驱动

**8. BDS Handoff — 行 31976: `BDS.HandoffToTse`**

BDS 完成启动项处理后交出控制权：
- 行 31773 `SignalAllDriversConnectedEvent` — 所有驱动连接完成
- 行 31809 `CallTheDispatcher` — 扫描启动选项
- 行 31925-31970 `UpdateBootOptionVariables` → `ReadBootOptions` → `CollectBootDevices` → `SaveBootOptions` — 启动项枚举和排序
- 行 31976 `HandoffToTse` — BDS 交出控制权给 TSE (AMITSE / OS Loader)
- 行 31978 `[AMITSE]` — Boot Manager 开始执行

## 练习 2：UEFITool ROM 结构探索

步骤：下载 UEFITool (github.com/LongSoft/UEFITool) → 打开 BIOS ROM (.bin/.rom) → 找到并展开 FV_RECOVERY (含 PEIMs)、FV_MAIN (含 DXE Drivers)、任意 PEIM 的 FFS → Section 结构。

| 项目 | 观察结果 |
| ---------------------------------------- | ------------------------------------------------------------------------ |
| ROM 文件大小 | 32MB |
| FV_RECOVERY 偏移与大小 | 0x01F50000 704KB |
| FV_MAIN 偏移与大小 | 1071000h 7160KB |
| PEIM 数量 (FV_RECOVERY) | 48 |
| DXE Driver 数量 (FV_MAIN) | 226 |
| 任一 FFS 文件的 Section 类型 | 4F1C52D3-D824-4D2A-A2F0-EC40C23C5916，类型：Freeform subtype GUID |
| 是否有压缩 | 有，算法：LZMA |
