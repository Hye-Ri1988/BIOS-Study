# Intel GOP 与 HDMI 显示链路（Graphics Output Protocol & Display Interface）

---
## 一、显示接口概览与信号链路

| 接口 | 信号类型 | 最大分辨率 | 热插拔 | 音频 | TGL 支持 |
| --- | --- | --- | --- | --- | --- |
| HDMI 2.0b | 数字 TMDS | 4K@60Hz | 支持 | 支持 | 原生 |
| DP 1.4a | 数字 8b/10b | 8K@30Hz | 支持 | 支持 | 原生 |
| eDP 1.4 | 数字 8b/10b | 5K@60Hz | N/A | N/A | 原生（内屏） |
| DP++（双模） | 数字/模拟 | 4K@60Hz | 支持 | 支持 | 需 Level Shifter |
| VGA | 模拟 RGB | 2K@60Hz | 不支持 | 不支持 | Legacy PCH |

> [!note] TMDS 与 8b/10b 
> HDMI 的 TMDS（Transition Minimized Differential Signaling）使用自有的编码（数据 2 bit 直接编码、6 bit 走 XOR/XNOR 最小化跳变），是"直流平衡 + 最小跳变"编码；DP 的 Main Link 才是标准的 8b/10b 编码。课件表格中 HDMI 标"TMDS"、DP 标"8b/10b"，两者刻意区分，注意不要混用。

信号链路（Signal Chain）从 GPU 到面板分六段：

```
CPU/GFX ──> DPLL ──> DDI/PHY ──> 连接器 ──> 线缆 ──> 面板
 像素渲染    时钟生成    信号编码    物理接口    传输      显示
```

> [!info] 显示链路架构图
> 下图以分层容器方式展示 GOP 固件层、GPU 硬件信号链（GFX→DPLL→DDI/PHY→连接器→线缆→面板）、显示器侧通道（HPD/DDC/GMBUS/EDID）与 OS 交接层（OpRegion/BGRT）的整体协作。GOP/BIOS 的职责边界仅覆盖 GFX→DPLL→DDI/PHY 前三段，线缆与面板无需 BIOS 参与。

![[gop_hdmi_chain.svg|640]]

BIOS（GOP）的职责边界在课件里说得很清楚：**只配置 CPU/GFX → PLL → DDI/PHY 这一段**，线缆和面板无需 BIOS 参与；但 EDID 数据决定了显示器支持哪些模式，进而决定 GOP 暴露哪些分辨率选项。

## 二、GOP：UEFI 图形输出协议

### 2.1 GOP vs VGA BIOS

GOP 是 UEFI 2.0 引入、现行 UEFI Spec（2.10）Chapter 12.9 定义的标准图形输出协议。它替代的是 Legacy 世界的 VGA BIOS：

| 维度 | VGA BIOS（Legacy） | GOP（UEFI） |
| --- | --- | --- |
| 调用方式 | INT 10h 中断 | 标准 UEFI Protocol |
| 代码形态 | 实模式 16-bit OptionROM | 原生 EFI 驱动（.efi） |
| 依赖 | 需要 CSM 支持 | 无需 CSM |
| 帧缓冲 | VGA 窗口 + 平面模式 | 线性帧缓冲（Linear Framebuffer） |
| 安全/速度 | 实模式慢、不受保护 | DXE 下原生执行，更快 |

Intel GOP 由四个组件构成：

| 组件 | 阶段 | 职责 |
| --- | --- | --- |
| IntelGraphicsPeim.efi | PEI | 早期图形初始化（POST logo 前） |
| IntelGopDriver.efi | DXE | GOP 协议驱动本体 |
| Vbt.bin | 数据 | Video BIOS Table，显示配置 |
| GopPolicyInitDxe | DXE | 平台策略初始化（VBT 选择 / Lid） |

### 2.2 EFI_GRAPHICS_OUTPUT_PROTOCOL 接口

GUID `{0x9042a9de, 0x23dc, 0x4a38, {0x96, 0xfb, 0x7a, 0xde, 0xd0, 0x80, 0x51, 0x6a}}`，定义在 EDK2 `MdePkg/Include/Protocol/GraphicsOutput.h`。三个方法：

- **QueryMode()**：查询指定模式的分辨率/像素格式。`Info` 由驱动内部分配，大小由 `SizeOfInfo` 返回——因为 `EFI_GRAPHICS_OUTPUT_MODE_INFORMATION` 结构随 UEFI 版本演化，不能直接 `sizeof()`。
- **SetMode()**：切换显示模式，成功后屏幕清黑。`ModeNumber` 须在 `[0, MaxMode-1]`，否则返回 `EFI_UNSUPPORTED`。
- **Blt()**：块传输，四种操作——`EfiBltVideoFill`（填充）、`EfiBltVideoToBltBuffer`（截屏）、`EfiBltBufferToVideo`（贴图）、`EfiBltVideoToVideo`（搬移）。

```c
// MdePkg/Include/Protocol/GraphicsOutput.h（节选）
typedef struct {
  UINT32  Version;
  UINT32  HorizontalResolution;
  UINT32  VerticalResolution;
  EFI_GRAPHICS_PIXEL_FORMAT PixelFormat;   // RGB / BGR / BitMask / BltOnly
  EFI_PIXEL_BITMASK         PixelInformation;
  UINT32  PixelsPerScanLine;
} EFI_GRAPHICS_OUTPUT_MODE_INFORMATION;

typedef struct {
  UINT32  MaxMode;
  UINT32  Mode;
  EFI_GRAPHICS_OUTPUT_MODE_INFORMATION *Info;
  UINTN   SizeOfInfo;
  EFI_PHYSICAL_ADDRESS FrameBufferBase;   // 帧缓冲物理地址
  UINTN   FrameBufferSize;
} EFI_GRAPHICS_OUTPUT_PROTOCOL_MODE;
```

> [!warning] 像素字节序坑：BGR 而非 RGB
> 常规 GOP 模式使用 `PixelBlueGreenRedReserved8BitPerColor`，即每像素 32 位，内存字节序是 **B（byte0）G（byte1）R（byte2）reserved（byte3）**。`EFI_GRAPHICS_OUTPUT_BLT_PIXEL` 的成员顺序同样是 `{Blue, Green, Red, Reserved}`。用 GOP 画图或做 framebuffer 直写时，直接往 FrameBufferBase 写 0x00RRGGBB 会得到红蓝互换的画面。

### 2.3 EDID 协议族与 Override 机制

UEFI 对 EDID 定义三个协议：

| 协议 | 含义 |
| --- | --- |
| EFI_EDID_DISCOVERED_PROTOCOL | 从显示器读到的原始 EDID |
| EFI_EDID_ACTIVE_PROTOCOL | 当前生效的 EDID（可能被覆盖） |
| EFI_EDID_OVERRIDE_PROTOCOL | 平台级覆盖入口 + HPD 控制 |

EDID 本身是 128 字节 Base Block：厂商/产品 ID、分辨率与刷新率、详细时序描述（DTD）、物理尺寸；HDMI 场景还会带 CEA-861 扩展块（音频格式 LPCM/AC3/DTS、HDMI Vendor Specific Data Block——2.0 标志就藏在这里）。

### 2.4 OpRegion：BIOS 与 OS 驱动的交接区

课件提到 GOP "为 OS 传递显示信息（OpRegion）"，这是 Intel 平台显示交接的关键机制，值得展开：

- **ASLS 寄存器**：iGFX（PCI B0:D2:F0）配置空间 offset 0xFC（ASL Storage），固件把 OpRegion 物理地址写进去，OS 显示驱动据此找到共享区。
- **OpRegion 结构**：以签名 `"IntelGraphicsMem"` 开头，内部按 Mailbox 划分：Header（0x000）、ACPI（0x100，显示切换/开合盖方法）、SWSCI（0x200）、ASLE（0x300，背光控制/环境光）、**VBT（0x400）**、ASLE_EXT（0x1C00）。
- OS 端 Linux i915 驱动解析 VBT 时，**优先从 ACPI OpRegion 读取，找不到再退回 PCI ROM**。
- 与之配套的还有 ACPI BGRT（Boot Graphics Resource Table）——固件把 logo 帧缓冲地址/尺寸写进 BGRT，Windows 在切换图形驱动时画面无闪烁，与 [[ACPI]] 笔记的配置表机制同源。

## 三、VBT：Video BIOS Table

VBT 是 Intel 专有的纯二进制显示配置表，存在固件 Firmware Volume 中（以 FFS 形式、按特定 GUID 存放），由 GOP 驱动在 DXE 阶段通过 `GetVbtData()` 获取。VBT 结构（依据 Linux 内核 `Documentation/gpu/intel-display/vbt.rst`）：

```
VBT Header（"$VBT" 签名，20 字节）
  ├─ version / header_size / vbt_size / vbt_checksum
  ├─ bdb_offset ──────────────┐
  └─ aim_offset[4]            │
BDB Header（"BIOS_DATA_BLOCK" 签名）
  ├─ version / header_size / bdb_size
  └─ 数据块链表：每个块 = 1 字节 Block ID + 2 字节 Size + 数据
```

| BDB Block ID | 内容 | 用途 |
| --- | --- | --- |
| 1 | General Features | 全局显示特性 |
| 2 | General Definitions | **Child Device Table**（端口/连接器定义） |
| 12 | Driver Features | 启动设备选择、boot mode |
| 22 | SDVO LVDS Options | LVDS/内屏选项 |
| 27 | eDP Block | eDP 面板参数（背光、PSR、电源时序） |
| 40/41/42 | LVDS Options / LFP Data | 内屏时序与 LFP 数据 |
| 53 | MIPI Sequence | MIPI DSI 时序序列（块长字段特殊） |

Child Device 是 VBT 的核心：每个 child device 条目描述一个物理连接点——设备类型（HDMI/DP/eDP/LVDS/MIPI）、DVO Port（映射到 DDI A/B/C/D）、DDC 引脚、HPD GPIO、支持标志。工程 `OemGopVbt/Vbt.json` 中定义了 13 个 child device（每个含 Primary/Secondary 设备类型），而 eDP 相关条目出现 1094 次、HDMI 105 次、DisplayPort 100 次、MIPI 170 次——一份 VBT 同时覆盖内屏 eDP、外接 HDMI/DP 与 MIPI 的候选端口，实际哪个生效由端口检测与 Boot Display 策略决定。

> [!tip] VBT 的编辑链：Vbt.json → discon → Vbt.bin
> 现代 AMI 平台 VBT 的源文件是 JSON（人可读、可版本控制），经 Intel 的 discon 工具编译成二进制 Vbt.bin 烧入固件。工程 `OemGopVbt/` 下 Vbt.bin 与 Vbt.json 成对存在；`CvteGopSwitch/` 下则有 Vbt.bin + Vbt_lvl5/6/7.bin 三个变体。

## 四、DDI 端口与 HDMI/DP 链路细节

Intel 平台通过 DDI（Digital Display Interface）端口连接显示器，每个 DDI 可配置为 HDMI、DP 或 eDP 模式。课件以 Tiger Lake UP3 为例：

| DDI Port | 典型用途 | 支持接口 |
| --- | --- | --- |
| Port A | eDP 内屏（CPU 直连） | eDP |
| Port B | 外接 | HDMI 2.0b / DP 1.4a / DP++ / MIPI |
| Port C | 外接 | HDMI 2.0b / DP 1.4a / DP++ |
| Port D | 外接 | DP 1.4a（TC/Type-C 场景） |

每个端口配套两类物理通道，都在 VBT 里按端口独立开关：

- **HPD（Hot-Plug Detect）**：GPIO 引脚（DDSP_HPD0~3）检测显示器插拔，事件经 GPE 上报 ACPI，由 [[ACPI]] 通知 OS 驱动。VBT 配置项如 `DdiPortBHpd = Enable`。
- **DDC（Display Data Channel）**：走 I2C 读 EDID。Intel 的实现是 **GMBUS** 控制器（Graphics Memory Bus，Intel 专用 I2C），寄存器在 GFX BAR 内（GMBUS0 引脚选择 / GMBUS1 命令 / GMBUS2 状态 / GMBUS3 数据 / GMBUS4 速率 / GMBUS5 超时），GPIO 复用为 HDMI_GMBUS_SCL/SDA。VBT 配置项如 `DdiPortBDdc = Enable`。

> [!note] GMBUS 与 [[SMBus & SPD]] 笔记中的 SMBus 是同族不同物
> GMBUS 是 Intel 图形单元内置的 I2C 主机，专用于 DDC/EDID；SMBus 是 PCH 上的系统管理总线（D31 功能块，0xEFA0 I/O 基址）。两者都是 I2C 变体，但寄存器模型、地址空间、用途完全不同，排障时不要混淆。

**HDMI TMDS 带宽**：HDMI 2.0 用 3 条 TMDS data lane + 1 条 clock lane，单 lane 6 Gbps，总 18 Gbps，对应 4K@60Hz 4:4:4 8bit。HDMI 2.1 改用 FRL（Fixed Rate Link）4 lane 最高 48 Gbps。课件 18Gbps 的数值即 HDMI 2.0 的 TMDS 总带宽。

**DP++（Dual Mode DP）**：同一端口可输出 DP 信号或降级为 HDMI/DVI（通过 Level Shifter 芯片做 TMDS 转换），VBT 中需同时配置 DP + HDMI 两套参数，常见于 Dock 转接场景。VGA 属模拟接口（DAC R/G/B + H/V Sync），新平台逐步淘汰，工控主板仍在用。

## 五、实训工程源码对照（AlderLake，C:\TEST\ib.iw68.xa03）

课件是 Tiger Lake UP3 视角，实训工程为 AlderLake（IB.IH61.XA01），整体模型一致，可直接对照：


`OemGopVbt/` 目录实际存在 `IntelGopDriver_17.0.1088.efi` 与 `IntelGopDriver_Old.efi` 两个版本，当前启用 17.0.1088。VBT 在 FV 中的定位靠 **FFS GUID**，即 IntelSiliconPkg 的 `PcdIntelGraphicsVbtFileGuid`——GOP 驱动靠这个 GUID 从固件卷里取 VBT，对应课件第 15 页"VBT GUID 是否正确"的排查点。

**② EDID Override 钩子（AmiModulePkg/AmiGopPolicy/AmiGopPolicy.c）**

课件第 9 页的代码样例在工程里真实存在：`OEM_EDID_OVERRIDE_PROTOCOL_SUPPORT` 编译开关控制，`AmiGopEdidOverrideGetEdid()` 遍历 `OemGopEdidOverrideGetEdidList[]`（OEM 通过 eLink 注入的函数数组，见 [[Aptio V eModule_oem & Elink]]），默认实现 `AmiDefaultGopEdidOverrideGetEdid` 返回 128 字节 EDID 或 `EFI_UNSUPPORTED`。这正是"固定分辨率、绕过损坏 EDID"的平台扩展点。

**③ 多 VBT 切换的两个层级**

- 按 BoardId 切换：`AmiChipsetModulePkg/Library/MultipleVBiosVbtLib.c` 的 `UpdatePcdIntelVBiosVbtFileGuid()`，根据 `AmiGetBoardInfo()` 得到的板号改写 `PcdIntelGraphicsVbiosFileGuid/PcdIntelGraphicsVbtFileGuid`，默认 VBT GUID 为 `{0xDCB132E7, ...}`。
- 按 Setup 选项切换：`OemPkg/Project/IB.IH61.XA01/CvteGopSwitch/CvteGopSwitch.c` 的 `CvtePlatformInfoPeiOverride()`——PEI 阶段读 Setup 变量 `LvdsSupport`（0/1/2），把 `AmiOemPlatformInfo->VbtFileGuid` 切到 `UEFI_GOP_VBT_FILE1/2/3`（对应 `Vbt_lvl7/lvl5/lvl6.bin`），并联动切换 Legacy VBIOS 的 Enable/Disable LVDS 版本。这正是课件第 15 页"OEM 定制 CvteGopSwitch 逻辑 + 多 VBT"的实现，本工程默认 `CvteGopSwitch_SUPPORT=0`（走 OemGopVbt 单 VBT），该模块作为参考实现保留。

**④ Setup 选项钩子**：`AmiChipsetModulePkg/NB/IntelSaGopSetup/IntelSaGopSetup.sdl` 以 `IntelGopSwitchFunction` 覆盖 AMI 默认的 `AmiDefaultGopSwitchFunction`（挂在 AmiGopPolicy 链上），提供 GOP 相关的 Setup 项扩展。

**⑤ 版本上报**：`Intel/AlderLakePlatSamplePkg/Telemetry/GopFirmwareVersionDxe` 读取 GOP 驱动固件版本写入 Telemetry，用于工厂/售后核对显示固件版本。

## 六、显示排障指南

课件给出三个高频场景的排查路径，整理为检查清单：

**场景 A：HDMI 无显示**

1. DDI Config：Port B/C 的 HPD/DDC 是否 Enable；
2. VBT：Port 是否定义为 HDMI、HDMI 版本（1.4/2.0）是否正确；
3. GPIO：HPD/DDC 引脚功能复用是否正确（可查 GPIO 表）；
4. EDID：UEFI Shell 下用工具读 EDID，确认有无 CEA-861 扩展块（无扩展块说明链路退化到 1.4 甚至检测失败）。

**场景 B：GOP Logo 不显示**

1. IntelGopDriver 是否加载（DXE 日志有无 GOP 安装消息）；
2. VBT 加载：`GetVbtData()` 是否成功、VBT FFS GUID 与 `PcdIntelGraphicsVbtFileGuid` 是否匹配；
3. 供电：eDP 面板的 Panel Power（VDD）时序是否满足（T1-T12）；
4. 显示设备选择：PrimaryDisplay 为 IGD 还是 PEG（独显优先会跳过 iGFX 初始化）。

**场景 C：VBT 选择错误（同板多面板）**

同一主板支持多种面板（LVDS 单/双通道、eDP 不同分辨率、HDMI 1.4/2.0）时，VBT 必须按实际面板选择。解法即上文工程对照：Setup 菜单加 VbtSelect 选项、GPIO 检测自动选择、或 OEM 定制 CvteGopSwitch/GopSwitchFunction 钩子。

> [!tip] 排查抓手
> 显示问题 80% 落在"VBT 配置"与"GPIO/供电"两层，而非 GOP 驱动本身：先确认驱动已加载、VBT GUID 对得上，再逐项核对端口 HPD/DDC/供电，最后用 EDID 数据反推链路协商结果。可参考 [[UEFI shell调试命令和APP]] 中的工具用法（读 PCI 配置空间确认 iGFX 是否枚举、读 EDID）。
