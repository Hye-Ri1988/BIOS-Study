# BIOS 学习日报 — 2026.07.20

## 一、理论学习：UEFI 固件六大启动阶段

| 阶段 | 要点 |
| ------- | -------------------------- |
| **SEC** | 用 CPU 缓存当临时内存，验明代码没被篡改 |
| **PEI** | 训练内存、初始化芯片，把 HOB 交给下一阶段 |
| **DXE** | 加载全部硬件驱动，建好完整的固件服务环境 |
| **BDS** | 决定从哪个设备启动，加载 OS |
| **RT** | OS 运行期间，提供少量固件服务（时间、变量读写） |
| **AL** | 系统休眠/关机/崩溃后，固件再次接管 |

各阶段要点：
- **SEC**：建立信任根，配置 Cache-as-RAM（CPU 缓存模拟内存）
- **PEI**：分两段——Pre-Mem（内存训练前）和 Post-Mem（内存可用后）。训练 DDR 是耗时大头
- **DXE**：代码量最大。先建运行环境，再按依赖关系逐个加载驱动。最后发 EndOfDxe 信号锁死安全边界
- **BDS**：读取 NVRAM 中的启动顺序，依次尝试，成功就加载 OS Loader

## 二、实践练习 1：真实平台日志分析（MTL 串口日志）

对照理论，在一条 MTL 平台启动日志中找到了 8 个关键分界线：

| 阶段切换点 | 日志行号 | 标志内容 |
| ----------- | ----- | ----------------------------------- |
| SEC 起点 | 2 | `FSP-T: CAR Init` |
| PEI 入口 | 22 | `PeiCore.Entry(FFF889FE)` |
| 内存训练 | 2451 | `MRC Entry` → `MemoryInit Complete` |
| PEI 切入 DRAM | 2994 | `EfiPeiMemoryDiscovered` |
| PEI 结束 | 22577 | `EfiEndOfPeiSignal` |
| DXE 入口 | 23113 | `DXE-Core.Entry(61164C70)` |
| DXE 锁定 | 30283 | `BDS.SignalEndOfDxe` |
| BDS 交接 | 31978 | `BDS.HandoffToTse` |

> 心得：以前看启动日志只觉得是一堆十六进制输出，现在能按阶段"断句"了，知道哪里是 SEC、哪里开始训内存、哪里 PEI 收工交给 DXE。

## 三、实践练习 2：用 UEFITool 拆解 BIOS ROM 文件

| 项目 | 结果 |
| --------------------- | -------------------------- |
| ROM 大小 | 32 MB |
| FV_RECOVERY 位置 | ROM 偏移 0x1F50000，大小 704 KB |
| FV_MAIN 位置 | ROM 偏移 0x1071000，大小约 7 MB |
| FV_RECOVERY 里 PEI 模块数 | 48 个 |
| FV_MAIN 里 DXE 驱动数 | 256 个 |
| Section 类型示例 | Freeform subtype GUID |
| 压缩算法 | **LZMA** |

要点：
1. FV_MAIN 整个被 LZMA 压缩存放在 ROM 里（7MB 压到约 2.3MB），启动时 PEI 阶段负责解压
2. FV_RECOVERY 不在 ROM 开头，而在 BIOS 区域靠后位置（约第 15MB 处）

## 四、总结与复盘

### 收获

1. 能把 UEFI 启动的 6 个阶段串成一条完整时间线，每个阶段"干什么活、怎么交给下一个阶段"有了基本认知
2. 掌握了看启动日志的基本方法——抓住 `PeiCore.Entry`、`EfiEndOfPeiSignal`、`DXE-Core.Entry` 等关键标识就能定位阶段边界
3. 学会了用 UEFITool / UEFIExtract 拆解 BIOS ROM，能找出 FV_RECOVERY、FV_MAIN，看懂 FFS 的 Section 结构和压缩信息

### 不足与改进

- 对 PEI 阶段内部 Pre-Mem / Post-Mem 切换的细节还不够熟悉，下次聚焦看内存训练前后的模块变化
- UEFITool 中嵌套 Volume 的展开逻辑（如 LZMA 解压后的子 Volume）需要更多练习
- 下次可以尝试对比不同平台的 ROM 布局差异
