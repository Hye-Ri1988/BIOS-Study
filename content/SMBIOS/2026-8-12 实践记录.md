# SMBIOS Type 140 定制实践记录（OemJYTianPkg + OemSetup）

---

SMBIOS 规范把 Type 0~46 都定义好了（BIOS 信息、系统信息、内存……），Type 140~255 是用于OEM的，规范一个字都没定义。所以结构自己定、内容自己填、显示自己写。

```
写：开机时  → 拼好一条记录 → 塞进 SMBIOS 表（gEfiSmbiosProtocol->Add）
读：进 Setup → 从表里把记录捞出来（GetNext）→ 更新页面字符串（InitString）
```

**写进表，读出来显示**。

---

定义类型结构（MySmbios.h）

```c
typedef struct {
  SMBIOS_STRUCTURE        Hdr;            // 4 字节固定头：Type/Length/Handle
  SMBIOS_TABLE_STRING     BIOSVersion;    // 字符串"索引 1"（不是内容！）
  SMBIOS_TABLE_STRING     ECVersion;      // 索引 2
  SMBIOS_TABLE_STRING     Manufacturer;   // 索引 3
  SMBIOS_TABLE_STRING     ProductName;    // 索引 4
} SMBIOS_TABLE_TYPE140;                   // Length = 8（不含字符串区）
```


| 函数                            | 作用                                         |
| ----------------------------- | ------------------------------------------ |
| `JYTianSmbiosType140Update()` | **总指挥**：先删旧的 → 分配内存 → 填字段 → 写字符串区 → 加进表    |
| `MySmbiosRemoveAll(Type)`     | 每次重跑前把旧的 Type 140 全删掉，防止重复添加               |
| `MySmbiosAddNew(SmbiosPtr)`   | 包装 `LocateProtocol + Add`，把记录真正塞进 SMBIOS 表 |
| `DetectEc(&Major, &Minor)`    | 问 EC 要版本号（本次实际拿到的是空实现，显示 0.00）             |

填字符串区的关键写法（就是"字符串拼接"）：

```c
StrArea = (CHAR8 *)SmbiosPtr.Hdr + SmbiosPtr.Hdr->Length;  // 指向结构末尾
AsciiStrCpyS (StrArea, MAX, "Main Board");   // 写第 1 个字符串
StrArea += AsciiStrLen (StrArea) + 1;        // 指针跳过一个 \0，到下一个位置
AsciiStrCpyS (StrArea, MAX, "IW68XA03A..."); // 写第 2 个
...
*StrArea = 0;                                // 最后补一个 0，字符串区结束
```

### 第 4 步：告诉编译系统依赖什么（MySmbios.inf）

[LibraryClasses] 里列这个库用到的库类：BaseLib、PrintLib、MemoryAllocationLib、EcLib、MyPrint……
[Protocols] 里写 `gEfiSmbiosProtocolGuid`（要用 SMBIOS 协议必须声明）。

### 第 5 步：挂载（JYTianSmbiosModule.sdl）——决定"什么时候跑"

```sdl
LibraryMapping                                # 把 MySmbios 库链接进 SmbiosBoard 驱动
  Class  = "NULL"
  Instance  = "OemJYTianPkg.MySmbios"
  Override  = "AmiCompatibilityPkg.SmbiosBoard"
End

ELINK                                        # 把函数挂进 OEM 更新链
  Name  = "JYTianSmbiosType140Update,"
  Parent  = "SmbiosOemUpdateList"
  InvokeOrder = AfterParent
End
```

**这里踩了大坑**：`SmbiosOemUpdateList` 这条链要等到 **ReadyToBoot**（准备启动操作系统时）才执行——但 Setup 界面在这之前就跑完了，所以 Setup 里永远查不到 Type 140（显示 N/A）。OS 里能读到，Setup 里读不到。

### 第 6 步：加一个提前执行的驱动（MySmbiosDxe.c/.inf）

让 Type 140 在 **EndOfDxe**（比 Setup 早）就进表：

```c
EFI_STATUS EFIAPI MySmbiosDxeEntry (...)
{
  // 注册 EndOfDxe 事件，到时回调自动执行
  return gBS->CreateEventEx (EVT_NOTIFY_SIGNAL, TPL_CALLBACK,
            MySmbiosOnEndOfDxe, NULL,
            &gEfiEndOfDxeEventGroupGuid, &mEndOfDxeEvent);
}

VOID EFIAPI MySmbiosOnEndOfDxe (EFI_EVENT Event, VOID *Context)
{
  gBS->CloseEvent (Event);          // 关掉，只跑一次
  JYTianSmbiosType140Update ();     // 提前把 Type 140 加进表
}
```

inf 里 `[Depex] gEfiSmbiosProtocolGuid`（协议装好才加载）+ `[Guids] gEfiEndOfDxeEventGroupGuid`（不然链接报错）。

### 第 7 步：Setup 界面显示（OemSetup 4 件套）

| 文件 | 改什么 |
|---|---|
| `OemMain\main.uni` | 加 4 个字符串：`STR_TYPE140_MANUFACTURER_NAME`（标签）+ `_VALUE`（内容，默认 "N/A"），Product 同理 |
| `OemMain\main.sd` | 在 Main 页加两个 `text` 项，引用上面 4 个字符串 |
| `SetupCallBack.c` | 写 `OemInitType140Info(HiiHandle, Class)`：查表 → 取字符串 → 更新页面 |
| `SetupCallBack.sdl` | `ELINK OemInitType140Info, Parent=SetupStringInit`（进 Setup 时自动调） |

Setup 侧的核心函数：

| 函数 | 作用 |
|---|---|
| `OemInitType140Info()` | 进 Setup 时被调用：`GetNext` 捞 Type 140 → 从字符串区按索引取内容 → 转 Unicode → 更新页面 |
| `InitString(HiiHandle, STRING_TOKEN(...), L"%s", 内容)` | 把内容写进 HII 字符串包，页面立刻显示 |
| `UnicodeSPrint(Display, Size, L"%a", Ascii)` | ASCII → Unicode 转换（SMBIOS 存 CHAR8，HII 要 CHAR16） |

## 最终验证

- 串口能看到两批 `[MySmbios]` 日志（EndOfDxe 一次 + ReadyToBoot 一次，确认双链路）
- Setup → Main 页显示 Type140 Manufacturer / Type140 Product 两行真实值
- OS 下 RWEveryting/HWiNFO 能读到 Type 140 原始记录
- EC 版本当前显示 0.00（工程 EC 未启用，EcLib 是空实现；要真版本需先开 EC）
