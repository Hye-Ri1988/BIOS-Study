# MyRTServices 实践记录：Runtime Services 三合一驱动

## 背景

学完 Runtime Services 后，用任务巩固理论。目标：GetTime（时间服务）、GetVariable/SetVariable（变量服务）、ResetSystem（复位服务）三个知识点**合成一个驱动** `MyRTServices`，在 SignOn 界面一次性展示。

## 方案设计

| # | 功能 | Runtime Service | 验证点 |
| --- | ---------------- | ----------------------------- | ------------------- |
| 1 | 显示系统时间 | `gRT->GetTime` | EFI_TIME 结构 |
| 2 | 变量自增计数 | `GetVariable` + `SetVariable` | 两次调用模式、NV 属性、跨启动持久化 |
| 3 | NVRAM 空间 | `gRT->QueryVariableInfo` | 变量空间概念 |
| 4 | F10 暖重启 / F11 关机 | `gRT->ResetSystem` | ResetType、不返回 |
| 5 | 重启原因传信 | 变量 + ResetSystem 组合 | 写变量 → 重启 → 下次启动读出 |

### 两个设计决策

- **按键交互不用死等**：入口执行一次性功能后立即返回，注册事件驱动按键检测（任务 8 救砖事故的教训）
- **变量 GUID 不进 dec**：`GetVariable` 运行时按 GUID 匹配，GUID 直接在 .c 定义，不扩大改动面

### 变量规划

| 变量 | 属性 | 用途 |
|---|---|---|
| `JYTianTestVar` | NV\|BS\|RT | UINT32 自增计数，验证 NVRAM 持久化 |
| `JYTianResetReason` | NV\|BS\|RT | 重启原因（0=无，1=Warm，2=Shutdown），跨启动传信 |

## 踩坑记录

### 事故 1：Depex 不完整 → 烧录后无限重启循环

- **现象**：第一版固件烧录后不开机（风扇转、黑屏、反复重启），Boot Block Recovery 恢复
- **根因**：Timer 回调里 `gST->ConIn->ReadKeyStroke` 没判 ConIn 是否就绪；Depex 只写了 `gAmiPostManagerProtocolGuid`，而 Post Manager 协议安装远早于 ConIn 连接 → 1 秒周期回调在 ConIn 就绪前触发 → 空指针 → 三倍故障 → 重启 → 又到该驱动 → 无限循环
- **修复**：回调判空 `if (gST->ConIn == NULL) return;` + Depex 改 `PostManager AND GOP`（任务 8 已验证的组合）

### 问题 2：F10/F11 无反应 → 轮询抢不过 TSE → 改 RegisterKeyNotify

- **现象**：修复崩溃后，显示/变量/空间全正常，唯独 F10/F11 不生效
- **根因**：键被 TSE 抢先消费。TSE 的 CheckForKey（HOOK8）毫秒级轮询 ConIn 队列，用户按键瞬间被 TSE 读走丢弃；1 秒周期的 Timer 轮询几乎必然抢不到。不是"1 秒窗口"问题，是消费速度不对等
- **正解**：弃轮询，改用 `SimpleTextInputEx` 的 `RegisterKeyNotify`——按键事件通知机制，不消费键队列、不与 TSE 竞争

### 问题 3：老 MdePkg 三连坑（EWDK 2016 配套版本）

| 坑 | 表现 | 处理 |
|---|---|---|
| `gST->ConInEx` 字段不存在 | 此版 `EFI_SYSTEM_TABLE` 只有 ConIn | 改 `gBS->LocateProtocol(&gEfiSimpleTextInputExProtocolGuid)`，INF [Protocols] 声明该 GUID |
| 头文件名 | 是 `Protocol/SimpleTextInEx.h`，不是 SimpleTextInputEx.h | include 用前者 |
| `EFI_KEY_NOTIFY_FUNCTION` 单参数 | 老规范定义 `(IN EFI_KEY_DATA *KeyData)` 一个参数，按新规范写两个参数 → C4113 → /WX 变 C2220 | 回调改单参数 |

> 第三坑的教训：写 `SimpleTextInputEx` 通知回调前，先看 `SimpleTextInEx.h` 里该 typedef 的实际签名，别直接按现代 UEFI 规范写。

## 知识点沉淀

1. **gRT 表**：`SystemTable->RuntimeServices` 的全局别名，和 gBS/gST 同级；时间/变量/复位三类服务都挂在它下面
2. **变量存储**：NV 变量最终落 **SPI Flash 的 NVRAM 区**（断电不丢），运行时读写走内存缓存；非 NV 变量只进内存。Flash 不能按字节覆盖，所以变量区是**追加式日志 + 垃圾回收 + 容错写（FTW）**
3. **CMOS ≠ NVRAM**：CMOS 是电池供电的 RTC 芯片 128 字节（传统 BIOS 设置）；NVRAM 是 SPI Flash 区域（UEFI 变量）。清 CMOS 会主动擦 NVRAM 变量区
4. **UEFI 键盘交互正解是 RegisterKeyNotify**（SimpleTextInputEx），不是轮询 ReadKeyStroke——事件通知不抢队列、每次按键必达
5. **TPL 差异**：RegisterKeyNotify 通知运行在 TPL_NOTIFY，ResetSystem 规范要求 TPL_APPLICATION——实践可直接调用（与 MyTimerDxe 技巧同源）
