# SMBus & SPD：系统管理总线与内存 SPD 的固件视角

SMBus（System Management Bus）是 Intel 于 1995 年提出的低速双线串行总线，本质上是给 PC 系统管理场景定制过的 I²C。对做过 MCU 的人来说，可以把 PCH 里的 SMBus Host Controller 想成 STM32 的 I2C 外设，SPD EEPROM 想成板上的 AT24C02——寄存器操作套路几乎一样，只是换成在 PCI 配置空间里找基址、在 I/O 空间里做传输。本篇覆盖 SMBus 与 I²C 的差别、PCH 控制器的寄存器模型、Byte Data / Block 两种主流访问方法的完整软件流程、DDR4 SPD 的 JEDEC 字节布局，以及 UEFI 侧的 `EFI_PEI_SMBUS2_PPI` / `EFI_SMBUS_HC_PROTOCOL` 抽象层，并对照本工程（AlderLake）源码。

---
## 一、什么是 SMBus：从 I²C 派生的管理总线

SMBus 由 Intel 1995 年提出，应用于 PC 系统的低速率通讯，两条线（SMBDAT / SMBCLK）控制主板上的设备并收集信息。设计目标与通用 I²C 不同：**面向系统管理**——电源管理、温度监控、风扇控制、电池（智能电池规范）、内存 SPD 读取，设备之间通过总线收发消息而不是各自拉控制线，从而节省管脚。

| 对比项 | SMBus | I²C |
| --- | --- | --- |
| 时钟频率 | 10 kHz 最小 / 100 kHz 最大（2.0 版；3.0 版 400 kHz，3.1 版可选 1 MHz） | 无最低限，标准 100 kHz / 快速 400 kHz / 快速+ 1 MHz / 高速 3.4 MHz |
| 逻辑电平 | 固定 TTL 阈值（VIL ≤ 0.8V，VIH ≥ 2.1V；3.0 版 VIH ≥ 1.35V） | 相对 VDD（0.3×VDD / 0.7×VDD） |
| 超时机制 | 强制 35 ms：SCL 拉低超过 35 ms 从设备自动复位释放总线 | 无，从设备一直拉低 SCL 时主机只能无限等待 |
| 错误检测 | 可选 PEC（Packet Error Checking，CRC-8） | 仅靠 ACK/NACK |
| 协议族 | 定义了标准化命令集（Quick / Byte / Word / Block / Process Call 等） | 只有基本读写时序 |
| 地址 | 7-bit，保留地址多（通用呼叫、ARP 0x61 等） | 7-bit 或 10-bit |
| 从设备应答 | 必须应答自己的地址（用于检测可移动设备如电池在位） | 允许不应答 |

> [!note]
> 频率差异的实际后果：I²C 主机访问 SMBus 从设备时，若时钟低于 10 kHz 或总线挂起超过 35 ms，SMBus 设备会按超时规则自行复位，导致时序不一致。反过来，普通 I²C 从设备没有超时机制，SMBus 主机对其操作是安全的——这也解释了为什么 SPD EEPROM（纯 I²C 设备）能被 SMBus 控制器顺利读写。

## 二、SMBus 主设备：PCH 控制器与 PCI 配置空间

PC 上 SMBus 总线的主设备是 **PCH 内部的 SMBus Host Controller**。它是一个 PCI 功能设备，软件的起点是 PCI 配置空间，运行时寄存器映射到系统 I/O 空间（也可选 MMIO）。

PCI 位置： D31:F4
### 2.2 配置空间关键寄存器

| 偏移 | 寄存器 | 作用 |
| --- | --- | --- |
| 10h–17h | SMBMBAR（Memory Base Address，64-bit） | MMIO 方式访问 SMBus 寄存器的基址 |
| 20h–23h | SMB_BASE（I/O Base Address） | I/O 方式访问 SMBus 寄存器的基址，bit15:5 有效（4KB 对齐域，实际 0xFFF0 掩码） |
| 04h | PCICMD（PCI Command） | bit0 = I/O Space Enable，bit1 = Memory Space Enable |
| 40h | HOSTC（Host Configuration） | bit0 = HST_EN（SMBus Host Enable），bit1 = SMB_SMI_EN，bit2 = I2C_EN（I²C 模式），bit3 = SSRESET（软复位） |

> [!tip]
> 传统 PCH EDS 中 **HOSTC(40h) bit0 = SMBus Host Enable**、bit3 = SSRESET，与 PPT "BIT0 Enable/Disable、BIT3 Reset controller" 的说法吻合。从 8 系列/C220 起 HOSTC 新增 **bit4 = SPD Write Disable**：置 1 后禁止写入 SMBus 地址 50h–57h，用于保护内存 SPD 不被意外改写，BIOS 读 SPD 不受影响。

本工程 `Sb.h` 对应定义（D31:F4）：

```c
#define R_SB_SMBUS_BASE_ADDR        0x20    // SMBus I/O base address register
#define R_SB_SMBUS_PCICMD           0x04    // PCI Command Register
#define R_SB_SMBUS_HOST_CONFIG      0x40    // SMBUS Host Configuration register
```

### 2.3 SMB_BASE 的默认值与 FSP 一致性

SMB_BASE 没有固定的硬件默认地址，由固件在 POST 早期编程，默认取 **0xEFA0**。本工程 `AmiChipsetModulePkg/Sb.sdl` 有明确注释：

> "Intel has no policy to pass SmbusBar address to FSP binary, so keep the default value of SmbusBar is 0xEFA0 that is the same as PeiSaPolicyLib.c."

```c
// Sb.sdl
Name  = "SMBUS_BASE_ADDRESS"
Value = "0xEFA0"
```

> [!warning]
> SMBus BAR 地址必须与 FSP / PeiSaPolicy 保持一致，否则 PEI 阶段 FSP 初始化内存时按错误的 I/O 基址读 SPD，直接导致内存训练失败。

### 2.4 为什么 PEI 早期只能用 I/O 方式

PPT 明确指出：EFI BIOS 在 PEI 阶段、内存尚未初始化时访问 SMBus 设备必须走 **SMB_BASE（I/O-mapped）**，不能用 SMBMBAR（mem-mapped）。原因：

1. **鸡生蛋问题**：内存初始化（MRC / FSP）本身就要先读 SPD 拿到时序参数才能配置内存控制器——DRAM 还没可用，自然不能把 SMBus 寄存器映射到内存地址空间访问；
2. **I/O 空间天生可用**：x86 的 I/O 端口空间不经过内存控制器，CPU 复位后即可用，SMBus 控制器只要开了 PCICMD 的 I/O Enable 就能访问；
3. **MMIO 需要前提**：SMBMBAR 是 64-bit 内存 BAR，要等 PCI 枚举完成、地址窗口分配好才可用，PEI 早期（尤其是 FSP-T/M 阶段）不满足。

## 三、SMBus 从设备与从设备地址

### 3.1 常见从设备

PC 系统上常见的 SMBus 从设备：

| 从设备 | 用途 |
| --- | --- |
| Clock Generator | 主板时钟芯片，配置各路时钟频率 |
| SPD EEPROM | 每根内存条上的配置信息芯片（详见第六章） |
| 电池（智能电池） | 笔记本电池的 SBS 接口：电量、温度、充放电控制 |
| 温度传感器 / 风扇控制器 | 散热管理 |
| PMBus 电源设备 | 数字电源（PMBus 是构建在 SMBus 之上的高层协议） |

### 3.2 从设备地址与 XMIT_SLVA 寄存器

每个从设备有唯一的 **7-bit 从设备地址**。PCH 侧把它写入 **Transmit Slave Address 寄存器（SMB_BASE + 04h）**：

- bit7:1 = 从设备地址（7-bit）
- bit0 = R/W#：1 表示读，0 表示写

```c
// Sb.h —— SMBus I/O 寄存器（基址 = SMB_BASE，默认 0xEFA0）
#define SMB_IOREG_HST_STS        0x00   // Host Status Reg.
#define SMB_IOREG_HST_CNT        0x02   // Host Control Reg.
#define SMB_IOREG_HST_CMD        0x03   // Host Command Reg.
#define SMB_IOREG_XMIT_SLVA      0x04   // Transmit Slave Address Reg.
#define     XMIT_SLVA_RW         0x01   // R/W#
#define SMB_IOREG_HST_D0         0x05   // Host Data 0
#define SMB_IOREG_HOST_BLOCK_DB  0x07   // Host Block Data Byte Reg.
#define SMB_IOREG_AUX_CTL        0x0d   // Auxiliary Control Reg.
```

> [!note]
> **0xA0 与 0x50 的表示法陷阱**：SMBus 规范里从设备地址是 7-bit（如 SPD = 0x50 = 101_0000b），但资料和工具里常见 8-bit "地址字节"写法（0xA0 = 1010_0000b，bit0 已并入 R/W 位）。0xA0 实际是 "0x50 左移 1 位 + 写位"。本工程 Token `NB_DIMM0_SMBUS_ADDRESS = 0A0h` 存的就是地址字节；而 `Execute()` 接口传入的是 7-bit 地址，函数内部 `bSlAddr = SlaveAddress.SmbusDeviceAddress << 1` 再拼 R/W 位。混用两套表示法是读 SMBus 代码最常见的坑。

## 四、访问方法：协议族与 PCH 支持情况

SMBus 2.0 规范定义了完整的命令协议族。PPT 列了 8 个名字（Quick, Byte, Byte Data, Word Data, Process Call, Block, I2C Read, Block Process），其中 **I2C Read 不是 SMBus 标准协议**，而是 PCH 控制器额外提供的 I²C 兼容命令（SMB_CMD = 18h），专门用于连续读 EEPROM 这类纯 I²C 设备。

PCH Host Controller 实际支持的命令编码（HST_CNT 的 bit4:2，掩码 1Ch）：

| SMB_CMD 编码 | 命令 | 用途 |
| --- | --- | --- |
| 00h | Quick Command | 只有地址+R/W 的开关命令（如电池电源开关） |
| 04h | Byte（Send/Receive Byte） | 无命令码的单字节收发 |
| 08h | **Byte Data** | 指定寄存器（命令码）读写 1 字节——SPD 逐字节读 |
| 0Ch | Word Data | 指定寄存器读写 2 字节 |
| 10h | Process Call | 写命令+参数后立即读结果（如电池询问电量） |
| 14h | **Block** | 带长度计数的多字节连续读写（最长 32 字节） |
| 18h | **I2C Read** | PCH 扩展命令，无命令码的连续读，适合 EEPROM |
| 1Ch | Block Process | Block 版本的 Process Call |

> [!tip]
> PPT 的工程结论：**PCH 上读 SMBus 推荐 Byte Data 或 I2C Read；写用 Byte Data；不建议用 Block**。原因：PCH 的 Block 传输需要软件逐字节处理 BYTE_DONE 状态、在倒数第二个字节时手工置 LAST_BYTE，且长度寄存器上限 32 字节（本工程 `Execute()` 中 `if (bLength > 32) bLength = 32;` 即为该约束），效率低、易出错。

### 4.1 Byte Data 读流程（伪代码）

```c
// 读 SPD Byte：SlaveAddr(7bit)=0x50, 命令码=SPD 内偏移 reg
UINT16 base = SMB_BASE;                       // PCI CFG 0x20 读出，默认 0xEFA0

// ① 取总线所有权：等 IUS(bit6) 清 → 等 HBSY(bit1) 清 → 清所有状态
while (IoRead8(base + 0x00) & 0x40);
while (IoRead8(base + 0x00) & 0x01);
IoWrite8(base + 0x00, 0xFF);                  // HST_STS 写 1 清零（W1C）

// ② 写命令码（= 要读的 SPD 寄存器偏移）
IoWrite8(base + 0x03, reg);                   // HST_CMD

// ③ 写从地址字节（7-bit<<1 | R/W#）
IoWrite8(base + 0x04, (0x50 << 1) | 1);       // XMIT_SLVA = 0xA1（读）

// ④ 启动传输：SMB_CMD=Byte Data(08h) | START(40h)
IoWrite8(base + 0x02, 0x08 | 0x40);           // HST_CNT

// ⑤ 等 INTR(bit1) 置位
while (!(IoRead8(base + 0x00) & 0x02));

// ⑥ 读数据
UINT8 data = IoRead8(base + 0x05);            // HST_D0

// ⑦ 清 INTR、释放所有权（写 IUS=1）
IoWrite8(base + 0x00, 0x02);
IoWrite8(base + 0x00, 0x40);
```

### 4.2 Byte Data 与 Block 的区别

PPT 第 23 页的总结，对照工程代码验证：

| 对比点 | Byte Data | Block |
| --- | --- | --- |
| 单次数据量 | 1 字节 | 多字节（≤ 32） |
| 等待的完成标志 | INTR（bit1） | BYTE_DONE（bit7），逐字节等待 |
| LAST_BYTE 位 | 不需要 | 读到/写到倒数第二个字节时置 `HST_CNT_LAST_BYTE(20h)` |
| 工程代码佐证 | `WaitForSmBusComplete()` 非 Block 检查 `HST_STS_INTR` | Block 检查 `HST_STS_BDS`；`ReadSmBusData()` 中 `if (i == Length8-1) IoWrite8(HST_CNT, HST_CNT_LAST_BYTE | SMB_CMD_BLOCK)` |

```c
// SmBusPorting.c —— 完成标志的选择
StsChkBit = (Protocol8 == SMB_CMD_BLOCK) ? HST_STS_BDS : HST_STS_INTR;
```

## 五、SMBus I/O 寄存器操作全流程（工程源码视角）

本工程 `AmiChipsetModulePkg/Library/SmBusLib/SmBusPorting.c` 的 `RwSmBusData()` 串起了完整的传输生命周期：

1. `BeforeSMBusTransfer`：等 INUSE_STS 清（他人占用结束）→ 等 HOST_BUSY 清 → 写 HST_STS_ALL 清状态。**IUS 是软件所有权位**：谁写 1 谁占用总线，退出时写 1 释放；
2. `WriteCommand`：写 HST_CMD = 命令码（对 SPD 就是寄存器偏移）；
3. `WriteSlAddr`：写 XMIT_SLVA = 7-bit 地址 <<1 | R/W#；
4. `WriteSMBusData`：写操作时把数据写入 HST_D0..；Block 写则先写长度到 HST_D0、数据逐字节写 BLOCK_DB(07h)；
5. `StartSmBusTransition`：写 HST_CNT = 协议码 | PEC_EN(可选) 再写一次 = 协议码 | START 触发传输；Block 前还需清 TCO 状态寄存器（`WRITE_IO8_TCO(TCO_IOREG_STS2, 2)`）；
6. `WaitForSmBusComplete`：轮询 HST_STS，等 INTR（非 Block）/ BYTE_DONE（Block）/ ERROR，超时 0x6000 次；
7. `ReadSmBusData` / `WriteSmBusBlockData`：收尾数据搬运；
8. `ClearSmBusStatusAndDelay` + `AfterSMBusTransfer`：清 AUX_CTL 的 AAC 位、写 HST_STS 的 INUSE_STS 释放总线。

> [!warning]
> PCH 的 IUS（In Use Status）是软件约定的互斥机制，不是硬件仲裁：任何软件（BIOS、SMI handler、OS 驱动）在发起传输前都必须先清它再占用，完成后置回。多个组件同时访问 SMBus（如 SMI 里的温度读取 vs DXE 驱动）若不做这个握手，会互相破坏传输。

## 六、SPD 详解：内存条的"身份证"

### 6.1 什么是 SPD

SPD（Serial Presence Detect）是一组内存模组配置信息：P-Bank 数量、电压、行/列地址数、位宽、各种操作时序（CL/tRCD/tRP/tRAS/tRFC…），存放在内存条上一颗 **256 字节（DDR4 标准）EEPROM** 中，习惯上把整颗 EEPROM 也叫 SPD。SPD 的作用是让 BIOS 在 POST 中**直接读取**内存参数，省去逐项探测，并让模组厂商把最适配其时序写进去，实现"即插即用"。

| 项目 | 说明 |
| --- | --- |
| 存储介质 | 8-pin SOIC EEPROM（I²C 接口），位于 DIMM 上 |
| 容量 | DDR4：256 字节（0x00–0xFF）+ 扩展区；EEPROM 物理容量 512 字节 |
| 读写通道 | SMBus / I²C（从设备地址 7-bit 0x50–0x57） |
| 规范 | JEDEC：DDR4 SPD 见 JESD21-C 及 DDR4 SPD 文档（4.1.x）；DDR5 见 JESD400-5 |
| 消费方 | BIOS（MRC/FSP 内存初始化）、OS（dmidecode、wmic memorychip）、内存工具（RW、SPDTool） |

### 6.2 从设备地址：A0/A2/A4/A6

PC 上通常 2–4 根内存插槽，SPD 地址由 EEPROM 的 SA0/SA1/SA2 引脚在板级决定，一般为：

| 插槽 | 地址字节（8-bit） | 7-bit 地址 | 本工程 Token |
| --- | --- | --- | --- |
| Channel A - Socket 0 | 0xA0 | 0x50 | `NB_DIMM0_SMBUS_ADDRESS = 0A0h` |
| Channel A - Socket 1 | 0xA2 | 0x51 | `NB_DIMM1_SMBUS_ADDRESS = 0A2h` |
| Channel B - Socket 0 | 0xA4 | 0x52 | `NB_DIMM2_SMBUS_ADDRESS = 0A4h` |
| Channel B - Socket 1 | 0xA6 | 0x53 | `NB_DIMM3_SMBUS_ADDRESS = 0A6h` |

> [!tip]
> PPT 说 SPD 从设备地址为 "A0/A2/A4/A6（高 7 位）"——严谨的表述是：**7-bit 地址为 50h–53h，A0/A2/A4/A6 是含 R/W 位的 8-bit 地址字节**（0xA1/A3/A5/A7 为对应读地址）。工程 `SmBusPorting.c` 将 `NB_DIMM0_SMBUS_ADDRESS` 等放入保留地址表（`SmBusPlatformReservedAddress`），供 ARP 时避让。

### 6.3 DDR4 SPD 关键字节布局（JEDEC）

| 偏移 | 内容 | 说明 / 典型值 |
| --- | --- | --- |
| 00h | SPD 大小/器件/CRC 覆盖 | 常用 23h（512 字节器件、384 字节使用、CRC 覆盖 0–125） |
| 01h | SPD 修订版 | 4.1.x 各版对应 11h/12h 等 |
| 02h | 内存类型 | **0Ch = DDR4**；0Dh = DDR5 |
| 03h | 模块类型 | 1h = RDIMM，2h = UDIMM，3h = SODIMM，4h = LRDIMM |
| 04h | SDRAM 密度与 Bank 组 | 如 94h/95h（4/8Gb ×4/×8） |
| 0Ch | 模块标称电压 | 1.2V 等 |
| 12h | tCKAVGmin | 最小平均时钟周期（如 0.75ns = DDR4-2666） |
| 13h | tCKAVGmax | 最大平均时钟周期 |
| 17h | CAS Latency（CL） | 支持的 CL 值 |
| 18h | tAAmin | 最小 CAS 延迟时间（ns 换算） |
| 19h | tRCDmin | RAS 到 CAS 延迟 |
| 1Ah | tRPmin | 行预充电时间 |
| 1Bh–1Ch | tRASmin / tRCmin | 激活到预充电 / 激活到激活周期（高位在 1Bh） |
| 1Dh–20h | tRFC1/2/4min | 刷新恢复时间 |
| 7Eh–7Fh | CRC | 基配置区校验和（0–125 或 0–116 字节） |
| 80h–BFh | 模块特定区 | 模组厂商自定义（时序、热等） |
| 100h+ | 扩展功能块 | 制造商、序列号、部件号等（EEPROM 512 字节内的扩展区） |

时序换算示例：DDR4-2666 的 tCK = 1/2666MHz ≈ 0.75ns，若 CL=19，则实际 CAS 延迟 = 19 × 0.75 ≈ 14.25ns——SPD 里 tAAmin 就是按 ns 编码的，固件按 tAA/tCK 向上取整得到实际 CL 值。

> [!note]
> DDR5 的变化：SPD 扩展到 512 字节主区，地址仍为 50h–57h；字节 2 的类型码为 0Dh；新增电压 PMIC 相关字段与更细的时序粒度。数据布局整体规则（头区→时序区→模块区→扩展区）沿用 DDR4 思路。

### 6.4 BIOS 为何必须先读 SPD

没有 SPD，BIOS 只能按保守默认参数初始化内存，或逐项探测（慢且不可靠）。有了 SPD，MRC/FSP 在内存初始化早期就通过 SMBus 逐字节读出全部参数，配置内存控制器（IMC 的 MRx 寄存器、PHY 训练），从而在 DRAM 可用前完成"内存的初始化数据采集"。这也解释了前文"PEI 早期只能用 I/O 方式访问 SMBus"的必然性——**内存初始化的第一手数据源本身就跑在这条总线上**。

## 七、UEFI 抽象层：PPI 与 Protocol

固件代码通常不直接操作 I/O 寄存器，而是通过 UEFI 标准接口：

### 7.1 EFI_PEI_SMBUS2_PPI（PEI 阶段）

- 定义：`MdePkg/Include/Ppi/Smbus2.h`，GUID `gEfiPeiSmbus2PpiGuid = {0x9ca93627, 0xb65b, 0x4324, {0xa2, 0x2, 0xc0, 0xb4, 0x61, 0x76, 0x45, 0x43}}`
- 接口：`Execute` / `ArpDevice` / `GetArpMap` / `Notify`
- 本工程生产者：`Intel/ClientOneSiliconPkg/IpBlock/Smbus/LibraryPrivate/PeiSmbusLib/PeiSmbusLib.c`（FSP 侧）；`AmiChipsetModulePkg/SB/SmBus/SmBusPei.c` 在 PPI 安装后注册 ARP 回调，MRC 前检查从地址冲突

### 7.2 EFI_SMBUS_HC_PROTOCOL（DXE 阶段）

- 定义：`MdePkg/Include/Protocol/SmbusHc.h`，GUID `gEfiSmbusHcProtocolGuid = {0xe49d33ed, 0x513d, 0x4634, {0xb6, 0x98, 0x6f, 0x55, 0xaa, 0x75, 0x1c, 0x1b}}`
- 接口：`Execute` / `ArpDevice` / `GetArpMap` / `Notify`（后三者可返回 Unsupported）
- 本工程生产者：`Intel/ClientOneSiliconPkg/IpBlock/Smbus/Dxe/SmbusEntry.c`（安装 `gEfiSmbusHcProtocolGuid`）
- 消费者：`MdePkg/Library/DxeSmbusLib`（SmBusReadDataByte 等封装库）、`AmiChipsetModulePkg/NB/UpdateMemoryRecord`（读内存记录）

`Execute()` 的核心参数与操作枚举：

```c
// MdePkg/Include/IndustryStandard/SmBus.h（节选）
typedef enum {
  EfiSmbusQuickRead,  EfiSmbusQuickWrite,
  EfiSmbusReceiveByte, EfiSmbusSendByte,
  EfiSmbusReadByte,    EfiSmbusWriteByte,      // ← Byte Data
  EfiSmbusReadWord,    EfiSmbusWriteWord,
  EfiSmbusReadBlock,   EfiSmbusWriteBlock,     // ← Block
  EfiSmbusProcessCall, EfiSmbusBWBRProcessCall
} EFI_SMBUS_OPERATION;

EFI_STATUS
(*Execute)(IN CONST EFI_SMBUS_HC_PROTOCOL *This,
           IN EFI_SMBUS_DEVICE_ADDRESS SlaveAddress,   // 7-bit 地址
           IN EFI_SMBUS_DEVICE_COMMAND  Command,        // 命令码（SPD 偏移）
           IN EFI_SMBUS_OPERATION       Operation,
           IN BOOLEAN                   PecCheck,
           IN OUT UINTN                *Length,
           IN OUT VOID                 *Buffer);
```

> [!tip]
> PEI 与 DXE 的调用习惯：PEI 阶段拿 PPI 后直接调 `Execute`（对应底层走 `PeiSmbusLib` → PPI）；DXE 阶段优先用 `DxeSmbusLib` 的 `SmBusReadDataByte()` 等一行封装，或直接 `LocateProtocol` 拿 HC Protocol。底层实现最终都落到第二节、第五节讲过的 SMB_BASE + I/O 寄存器流程。标准 EDK2 实现位于 `MdeModulePkg`（`SmbusDxe`）；本工程为 AMI/Intel 自研实现，位于 `ClientOneSiliconPkg/IpBlock/Smbus`。


## 术语表

| 术语 | 含义 |
| --- | --- |
| SMBus | System Management Bus，Intel 1995 年提出的低速管理总线 |

| Host Controller | PCH 内的 SMBus 主控制器（本工程 D31:F4） |
| SMBMBAR / SMB_BASE | SMBus 寄存器的 MMIO / I/O 基址（后者默认 0xEFA0） |
| HOSTC | PCI 配置空间 40h，SMBus 主机使能/复位/SPD 写保护 |
| HST_STS / HST_CNT | 主机状态寄存器（INTR/BYTE_DONE/IUS 等）/ 主机控制寄存器（START/LAST_BYTE/命令码） |
| XMIT_SLVA | 发送从地址寄存器（bit7:1 地址，bit0 R/W#） |
| Byte Data / Block | SMBus 两种传输协议：单字节寄存器读写 / 多字节块读写 |
| PEC | Packet Error Checking，SMBus 可选的 CRC-8 校验 |
| ARP | Address Resolution Protocol，SMBus 从设备地址解析 |
| SPD | Serial Presence Detect，内存条上 256 字节配置 EEPROM |
| tCK / CL / tRCD / tRP | DRAM 时序参数：时钟周期 / CAS 延迟 / RAS-CAS 延迟 / 行预充电 |
| MRC | Memory Reference Code，内存初始化代码（FSP 的一部分） |
| IUS | In Use Status，SMBus 总线软件所有权位 |
| EFI_PEI_SMBUS2_PPI | PEI 阶段访问 SMBus 的标准 PPI |
| EFI_SMBUS_HC_PROTOCOL | DXE 阶段访问 SMBus 的标准 Protocol |
