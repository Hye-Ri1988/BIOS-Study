# 认识 CvteWatchdog Module — 各文件的存在价值

> 目录：[[#CIF 组件信息文件]] / [[#CvteWatchDog.sdl]] / [[#WatchDogDxe.inf 和 WatchDogPei.inf]] / [[#WatchDogDxe.c 和 WatchDogPei.c]] / [[#WatchDog.sd 和 WatchDog.uni]]

## CIF 组件信息文件

```text
// CIF = Component Information File（组件信息文件）
// 描述一个组件叫什么、文件放在哪、包含哪些 INF 模块和辅助文件
// CIF 是 AMI 构建系统里打包和复用功能模块的载体：
// 项目只要引用它的 RefName，就能把这个自包含的功能整体拉进工程

<component>
    name = "CvteWatchDog"   // 组件名称
    category = ModulePart   // ModulePart：可作为模块的子组件被工程引用
    LocalRoot = "OemPkg\Function\CvteWatchDog\" // 组件根目录
    RefName = "CvteWatchDog" // 项目通过这个名称引用组件

[INF]   // 声明本组件包含的可构建模块 INF 列表
"WatchDogPei.inf"   // PEI 阶段驱动模块
"WatchDogDxe.inf"   // DXE 阶段驱动模块

[files] // 声明本组件携带的辅助文件列表
"CvteWatchDog.sdl"  // 本 SDL 描述文件
"WatchDog.uni"  // 多语言字符串包（Setup 界面要显示的字符串）
"WatchDog.sd"   // Setup Definition 文件（watchdog 配置页的表单布局）
<endComponent>
```

> 个人理解：CIF 把相对独立的功能所需文件打包，项目引用 RefName 就能引入功能模块。引入其它功能写法一致，改对应 [INF]、[files] 即可。

## CvteWatchDog.sdl

```text
// sdl 可以让某个功能在不改动 AMI 底层基础代码的前提下自动添加到 BIOS 中

TOKEN
    Name  = "CvteWatchDog_SUPPORT" // 功能使能开关
    Value  = "1"
    Help  = "Main switch to enable CvteWatchDog support in Project"
    TokenType = Boolean
    TargetEQU = Yes  // 在 EQU 中生成
    TargetMAK = Yes  // 在 MAK 中生成
    Master = Yes     // Master Token，其它 Token 的使能状态依赖它
    TargetH = Yes    // 在 H 文件中生成，C 头文件可使用
    Token = "AMI_FSP_BIN_SUPPORT" "=" "0"  // 条件依赖：仅当平台未用 FSP 二进制时本功能生效
End

PATH    // 路径宏：集中管理路径，便于移植
    Name = "Watch_Dog_DIR"
End

ELINK // 把看门狗配置页面布局 .sd 注入 BIOS Setup
    Name  = "$(Watch_Dog_DIR)/WatchDog.sd"
    Parent  = "SETUP_DEFINITIONS"   // Setup 总定义，所有配置页布局都挂载在它下面
    InvokeOrder = AfterParent
End

ELINK // 把看门狗字符串文件注入 BIOS Setup
    Name  = "$(Watch_Dog_DIR)/WatchDog.uni"
    Parent  = "SetupStringFiles"
    InvokeOrder = AfterParent
End

INFComponent    // 添加看门狗模块
    Name  = "WatchDogDxe"
    File  = "WatchDogDxe.inf"
    Package  = "CvteModulePkg"
    ModuleTypes  = "DXE_DRIVER"
End

INFComponent
    Name  = "WatchDogPei"
    File  = "WatchDogPei.inf"
    Package  = "CvteModulePkg"
    ModuleTypes  = "PEIM"
End
```

> 个人理解：sdl 通过 Token 控制引入模块的开关与生效范围，通过 elink 实现模块间解耦与扩展。AMI 已写好基础模块并允许扩展，只需通过 elink 将功能注入项目 BIOS。归根结底，sdl 文件就是向整个 BIOS 描述 CIF 引入的功能组件包会产生什么影响、影响范围在哪里。

## WatchDogDxe.inf 和 WatchDogPei.inf

告诉 BIOS 系统这是什么模块、模块名、是 DXE 还是 PEI 阶段驱动、依赖哪些包和库。

## WatchDogDxe.c 和 WatchDogPei.c

实现模块功能逻辑的代码文件，让模块在系统中工作起来。

> inf 文件向整个系统声明自己，C 文件实现模块具体功能。声明和功能逻辑分开，类似普通 C 开发中的 C 文件和 H 文件。

## WatchDog.sd 和 WatchDog.uni

- **.sd**：让 C 代码实现的功能以界面形式展示给用户。`SETUP_DATA` 数据结构能把用户在 Setup 界面中的操作实际传递给 C 文件，改功能不必改源码重新编译
- **.uni**：决定 BIOS Setup 界面显示的字符串（目前只定义了英文）
