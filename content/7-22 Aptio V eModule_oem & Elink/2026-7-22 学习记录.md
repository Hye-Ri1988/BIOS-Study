# Aptio V eModule / OEM & eLink

## 什么是 SDL？

**SDL（System Description Language）** 是 AMI 为描述系统设计数据定义的专用语言。

关键特征：
- **跨模块共享**：同一份数据被多个 BIOS 模块复用
- **可分散定义**：可写在一个或多个 `.sdl` 文件中
- **由 AMISDL（Win32 工具）处理**：解析后生成各类构建文件

> SDL 的精髓是"一份数据，多种输出格式"。例如 PCI IRQ 路由信息只需在 SDL 中描述一次，即可同时生成 ACPI IRQ Routing Links、PCI BIOS Routing Table、Routing Interrupt Services、IOAPIC 条目（MP Table）。

AMISDL 内部两大部分：**SDL 解析器**（解析为中间数据结构）、**输出数据生成器**（针对不同模块生成各自数据）。

### AMISDL 输出格式

| 输出文件 | 格式 | 数据来源 |
|---|---|---|
| `TOKEN.EQU` / `TOKEN.INC` | Microsoft ASM | Token 对象 |
| `TOKEN.MAK` | Microsoft NMAKE | Token 对象 |
| `TOKENS.H` / `TOKENASL.H` | C/C++ 头文件 | Token 对象 |
| `TOKENS.ASL` | ACPI Source Language | Token 对象 |
| `OEMPIR.INC` / `OEMPIR.C` | PCI IRQ 路由数据 | PCIDevice / IRQLink |
| `IO.INC` / `IODEV.ASL` | Legacy 外设列表 | IODevice / LDevice |
| `EKERNEL.ASM` / `EKERNEL.INC` | eLink 表 | eLink 扩展机制 / Segment |
| `PCI_TREE.ASL` / `IRQROUT.ASL` | ACPI PCI 设备树 / IRQ 路由 | PCIDevice / IRQLink |
| `MODULES.MAK` | BIOS 模块列表 | Module 对象 |
| `PLATFORM_DSC` / `PLATFORM_FDF` | EDK II 平台描述文件 | INFComponent / FD_INFO 等 |

## SDL 核心对象（四大类）

- **设备描述类**：PCIDevice、SIODevice、IODevice/LDevice、RSVChipset
- **中断与路由类**：IRQLink、IOAPIC
- **模块与链接类**：Module、eLink+Segment、INFComponent、LibraryMapping、PCDMapping
- **固件布局类**：FD_INFO、FD_AREA、FFS_FILE、Path、OUTPUTREGISTER

它们层层支撑：设备提供硬件信息 → 中断把它映射成固件可识别格式 → 模块对象把代码接入构建 → 固件布局决定烧录位置。

### PCIDevice 对象

描述 PCI 设备配置。关键字段：`Name`、`Bus/Device/Function`、`SubClass/BaseClass`、`IRQ/IntPin`、`LinkDevID/LinkVenID`、`Fixed Resources/PowerBtn`。

```sdl
PCIDevice
    Name     = "USB Controller"
    Bus      = 0
    Device   = 20
    Function = 0
    SubClass = 0x03
    BaseClass= 0x0C
    IRQ      = 11
    IntPin   = 1
End
```

自动生成：`PCI_TREE.ASL`（ACPI PCI 设备树）、`IRQROUT.ASL`（含 PRxy PIC 模式、ARxy APIC 模式、PRSy _PRS 资源缓冲区）。

### Token 对象

Token 是构建时的**配置参数/功能开关**。字段：`Name`、`Value`、`Help`、`Master`、`Dependency`。
- `Value` 支持：引用其他 Token、算术/逻辑运算（`+ - * / | & ~`）、一元运算、括号、多遍解析
- `Master`/`Dependency` 实现从属关系：主 Token 被禁用时，所有从属 Token 一并失效

```sdl
Token
    Name  = "USB_Support"
    Value = "1"
    Help  = "Enable USB Support"
End
```

### IRQLink 与 IOAPIC

- **IRQLink（IRQ 路由链接）**：字段 `Name`（如 LNKA）、`IRQ`、`PossibleIRQs`、`Level/Edge`、`ActiveLow/ActiveHigh`。输出 ASL `_PRT`、PCI BIOS Routing Table、Routing INT Services。
- **IOAPIC**：字段 `Source`、`GlobalSystemInterrupt`、`Polarity`、`TriggerMode`。输出 MP Table IOAPIC 条目。

### Module / eLink / INFComponent / LibraryMapping / PCDMapping

这组对象是"把代码模块接入构建系统"的纽带：
- **Module**：定义模块列表 → `MODULES.MAK`
- **eLink**：可扩展链接，Parent 由驱动产生，Child 通过库函数添加
- **INFComponent**：映射 SDL 模块到 DSC `[Components]`（INF、Arch、ModuleType）
- **LibraryMapping**：库类覆盖（Class、Instance、Override），优先级高于 DSC 全局设置
- **PCDMapping**：SDL Token → PCD，使配置在 EDK II 中可被 PCD 机制访问

### 固件布局对象

- **FD_INFO**：Flash 设备信息（Name、Size、ErasePolarity）
- **FD_AREA**：区域定义（FV Region / FILE Region，含访问/内容/签名/更新属性）
- **FFS_FILE**：FFS 文件（Name、FD_AREA 引用、Priority）
- **Segment**：被 eLink→Segment 引用，定义输出格式与排列

## SDL 文件项：DSC / FDF / ACPI

AptioV 会**自动生成** `Platform.dsc` 与 `Platform.fdf`，以及多个 ACPI ASL 文件。

### DSC 区段 ↔ SDL 映射

| DSC 区段 | SDL 来源 |
|---|---|
| `[Defines]` | `PLATFORM_NAME` / `MACRO` / `DEBUG_MACRO` |
| `[Libraries]` | Library INF 列表 |
| `[LibraryClasses]` | LibraryMapping |
| `[PCD]` | PCDMapping / Token |
| `[Components]` | INFComponent |
| `[BuildOptions]` | SDL BuildOptions（`=` 追加，`==` 替换） |

**PCD 四种类型**：`PcdsFeatureFlag`（功能开关）、`PcdsFixedAtBuild`（构建时固定，存 code section）、`PcdsPatchableInModule`（可修补，存 data section）、`PcdsDynamic`/`PcdsDynamicEx`（运行时动态，模块间共享）。

**LibraryClasses 优先级（高→低）**：`[Components]` 关联 INF → `libraryclass.$(Arch).$(MODULE_TYPE)` → `libraryclass.$(Arch)` → `libraryclass.common`。

### FDF 区段支持情况

- `[FD]` Flash 设备：`FV Region`（支持）、`FILE Region`（支持）、`DATA Region`/`Capsule Region`（**不支持**）
- `[FV]` 固件卷：`Apriori Scoping`、`INF Statements`、`FILE Statements`；不支持 `DEFINE`/`Block`/`FV SET`
- `[Rule]` FFS 规则：配合 `[FV]` 的 INF 类型，定义 FFS 打包方式，控制 PE32/压缩/版本信息

```sdl
FD_INFO  Name = "PlatformFD"  Size = 0x00800000  ErasePolarity = 1  End
FD_AREA  Name = "FvMain"  FV = FvMain  BaseAddress = 0x0  Size = 0x0C0000  End
FFS_FILE Name = "MyModule"  FD_AREA = FvMain  Priority = 0  End
```

### ACPI 自动生成

- `TOKEN.ASL`：由 Token 生成，把 BIOS 配置暴露给 ACPI
- `PCI_TREE.ASL`：由 PCIDevice 生成设备树
- `IRQROUT.ASL`：由 PCIDevice + IRQLink 生成（PRxy/ARxy/PRSy）
- `DSDT.ASL`：默认包含上述三者
- `DsdtAsl.inf`：用户自定义 ASL 入口

## eLink 扩展机制

**核心思想**：eLink 是模块间的可扩展链接机制。驱动模块定义 **Parent eLink（扩展点）**，其他模块通过 **Child eLink** 把功能函数注册到该点，构建系统自动合并多个 Child 成函数表供 Parent 调用。

- **解耦**：OEM 可向 AMI 基础模块注入功能而不改原始代码
- **可组合**：多个子模块独立注册同一 Parent，构建自动合并
- **条件化**：通过 Token 条件控制

```
Parent eLink（驱动模块）
    ↓ LibraryMapping（映射连接）
Child eLink（库实现）
    ↓ 输出
token.mak 自动生成 eLink 列表 → MAK 生成包含函数列表的 H 文件 → 源文件 include 后使用
```

### 添加 eLink 的步骤

**添加 Parent eLink**：创建 MAK 文件生成定义 eLink 列表的 H 文件 → 源文件 include → eLink 自动在 `token.mak` 中生成。

**添加 Child eLink**：在已有/新建 Library 中实现 child eLink 函数 → 创建 LibraryMapping 关联 Parent 与 Child。

```sdl
LibraryMapping
    Class    = "NULL"
    Instance = "<PackageName>.<ModuleName>"
    Override = "<PackageName>.<ModuleName>"
End
```

### 典型 ELINK 应用

| 文件 | 用途 | 说明 |
|---|---|---|
| `HstiAmi.sdl` | 父+多子节点 | HSTI 安全测试注册 |
| `FlashSmiElinks.sdl` | Priority + Before/After | Flash 更新前后回调 |
| `AMITSE.sdl` | 多级链 + Priority | 源文件/库依赖/GUID |
| `FixedBootOrder.sdl` | BeforeParent | 启动顺序初始化 |
| `Variables.sdl` | 链式创建 | Secure Boot 密钥变量绑定 |
| `Oem_Microcode.sdl` | ReplaceParent + 多 Token | 微码文件替换 |

InvokeOrder 取值：`ReplaceParent`（替换父）、`AfterParent`（父之后）、`BeforeParent`（父之前）等。

### 示例 1：BDS Parent eLink

**Bds.sdl** 定义扩展点：
```sdl
ELINK
    Name = "BDS_CONTROL_FLOW"
    InvokeOrder = ReplaceParent
End
```

**Bds.c** 把函数表当回调列表执行：
```c
BDS_CONTROL_FLOW_FUNCTION *BdsControlFlowFunctions[] = { BDS_CONTROL_FLOW NULL };

VOID BdsEntry(IN EFI_BDS_ARCH_PROTOCOL *This) {
    for(i=0; BdsControlFlowFunctions[i]!=NULL; i++)
        BdsControlFlowFunctions[i]();
}
```

> SDL 定义扩展点 → MAK 生成函数表头 → C 代码把函数表当回调列表执行。OEM 只需添加 Child eLink 即可挂载，无需改 Bds.c。

### 示例 2：CRBCsp Child eLink

库实现函数 → INF 声明为 Library → SDL `ELINK` 注册为某 Parent 的 Child → `LibraryMapping` 让该库被 Parent 模块（此处 `AmiModulePkg.Bds`）链接，从而 Bds 构建时能拿到此函数。

## eModule 创建流程

### 四类核心文件

| 文件 | 用途 |
|---|---|
| SDL — FFS_FILE | 定义 FFS 文件属性，关联 FD_AREA、Priority |
| CIF | 组件信息文件（元数据） |
| INF | 模块信息文件（源码/库依赖/GUID） |
| DEC | 包声明文件（Package 接口） |

### INF 模块类型

| 类型 | 阶段 | 说明 |
|---|---|---|
| SEC | Security | 最先执行，CAR 初始化 |
| PEIM | PEI | 内存发现，HOB 传参给 DXE |
| DXE_DRIVER | DXE | 设备驱动、协议安装 |
| DXE_SMM_DRIVER | SMM | 系统管理中断处理 |
| UEFI_APPLICATION | UEFI | UEFI 应用程序 |

### eModule 类型总览

- **SEC 模块**：`CIF/INF/ASM`，CAR 初始化
- **PEI 模块**：`INF/C`，内存发现
- **DXE 模块**：`INF/C`，设备驱动
- **SMM 模块**：`SDL/INF`，SMM 处理程序
- **OEM Setup**：`SDL/SD/UNI/C`，多语言自定义 Setup
- **OEM Hooks**：`SDL`，回调函数
- **OEM INT15**：`SDL/ASM`，INT15 中断
- **Rom Hole**：`SDL/ASM/MAK/TXT`，ROM 空洞
- **FV_OEM / OEM Lib**：OEM 固件卷与库

### 文件结构示例

**CIF 组件信息文件**
```ini
<component>
    name = "SampleSetup"
    category = ModulePart
    LocalRoot = "SampleModulePkg\Setup\"
    RefName = "SampleModulePkg.Setup"
[files]
    "SampleSetup.sdl"
    "SampleSetup.sd"
    "SampleSetup.uni"
    "SampleSetup.c"
<endComponent>
```

**DEC 包声明文件**
```ini
[Defines]
DEC_SPECIFICATION  = 0x00010005
PACKAGE_NAME       = SampleModulePkg
PACKAGE_GUID       = CF782123-037C-4a5d-B118-46032E71D5AC
PACKAGE_VERSION    = 0.1
[Includes]
[LibraryClasses]
[Guids]
gSampleModulePkgTokenSpaceGuid = { 0x4152a89e, 0x9461, 0x4826, { 0x8a,0x76,0x5b,0x8c,0x78,0x2b,0x41,0x65 } }
[Protocols]
[Ppis]
```

**INF 模块信息文件（PEIM 示例）**
```ini
[Defines]
INF_VERSION   = 0x00010005
BASE_NAME     = SamplePei
FILE_GUID     = 779EE510-E504-4711-8976-CD7047ED4787
MODULE_TYPE   = PEIM
VERSION_STRING= 1.0
ENTRY_POINT   = SamplePeiEntryPoint
[Sources]
SamplePei.c
[Packages]
MdePkg/MdePkg.dec
AmiCompatibilityPkg/AmiCompatibilityPkg.dec
[LibraryClasses]
PeimEntryPoint
AmiPeiLib
[Depex]
TRUE
```

> 规律：不同阶段通过 `MODULE_TYPE` 区分，通过不同入口库（`PeimEntryPoint`/`UefiDriverEntryPoint`/`UefiApplicationEntryPoint`）接入对应执行环境。

### SDL — INFComponent 与 FFS_FILE

```sdl
INFComponent
    Name  = "SamplePei"
    File  = "Pei\SamplePei.inf"
    Package = "SampleModulePkg"
    ModuleTypes = "PEIM"
End

FFS_FILE
    Name  = "SamplePei"
    FD_AREA = "FV_BB"
    INFComponent = "SampleModulePkg.SamplePei"
End
FFS_FILE
    Name  = "SampleDxe"
    FD_AREA = "FV_MAIN"
    INFComponent = "SampleModulePkg.SampleDxe"
End
```

> `INFComponent` 告诉构建系统"有哪些模块、源码在哪、依赖什么"；`FFS_FILE` 告诉系统"编译好的模块分别放 Flash 哪个区域"。两者配合完成从源码到固件映像的映射。

## Debug Message 调试

> [!warning] 必要条件
> Debug 输出需**同时满足**：① 主机串口硬件连接正确（波特率/数据位/停止位/校验位匹配）；② SDL Token 中 Debug 级别参数配置正确。任一缺失都无法正常捕获。

控制维度：Debug 级别（Error Level）、Debug 输出方式、按模块设置 Debug 参数、通过 `PcdDebugPrintErrorLevel` 控制。

```sdl
TOKEN
    Name  = "DEBUG_MODE"
    Value = "1"
    Help  = "Main switch to enable/disable debug mode."
    TokenType = Boolean
    TargetMAK = Yes
End
```

### Trace 格式化参数

| 参数 | 说明 | 示例 |
|---|---|---|
| `%c` | 字符 | `'A'` |
| `%d` / `%ld` | 十进制（INT64 用 `%ld`） | `42` |
| `%g` | GUID | `{xxx-xxx-xxx}` |
| `%r` | 状态码 | `EFI_SUCCESS` |
| `%s` | 字符串（Null 结尾） | `"hello"` |
| `%S` | Unicode 字符串 | `L"hello"` |
| `%x` / `%X` / `%lx` | 十六进制（INT64 用 `%lx`） | `0xFF` |

## 总结

1. **SDL 描述语言是核心**：一份数据、多种输出；覆盖设备/中断/模块/固件布局；自动生成 DSC/FDF/ASL；Token 统一管理配置
2. **eLink 扩展机制实现灵活扩展**：Parent/Child 解耦；LibraryMapping 连接；`token.mak` 自动生成函数列表；与 EDK II 无缝集成
3. **eModule 创建流程标准化**：覆盖 SEC→PEI→DXE→SMI；固定文件结构（SDL+INF+CIF+DEC）；支持 OEM 自定义扩展
4. **Debug Message 调试是定位关键**：Token 控制级别、串口输出、Trace 格式化、`PcdDebugPrintErrorLevel` 精细控制

> 一句话串联：用 **SDL** 描述一切 → 由工具**自动生成** DSC/FDF/ACPI → 用 **eLink** 解耦扩展 → 按 **eModule** 标准落地代码 → 用 **Debug** 验证定位。这就是 AptioV OEM 开发的完整闭环。
