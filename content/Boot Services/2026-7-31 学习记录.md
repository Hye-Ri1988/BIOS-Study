# Boot Services

Boot Services 是 UEFI 启动阶段（从 DXE 到 BDS）可用的底层服务集合。生命周期止于将控制权移交 OS 之前：一旦调用 `ExitBootServices()`，整张服务表立即失效，此后只能使用 Runtime Services。

所有服务通过全局指针 `gBS`（类型 `EFI_BOOT_SERVICES *`）调用，`gBS` 本质是一张函数指针表。

## 1. 入口来源与生命周期

`gBS` 来自 `EFI_SYSTEM_TABLE` 的 `BootServices` 字段。EDK II 的 `UefiBootServicesTableLib` 在库初始化时从 `SystemTable->BootServices` 取出并缓存为 `gBS`，包含该库后即可直接使用。

注意：Boot Services 在 SEC/PEI 阶段尚不存在。参数在早期阶段的传递依赖 PEI HOB，二者属于不同阶段，不应混淆。

与 Runtime Services 的区别：Runtime 在 OS 启动后仍可使用（需经重定位），如变量、时间、复位等服务；Boot 仅在启动期有效，交权之后访问会导致错误。

## 2. 服务总表

| 类别 | 代表函数 | 作用 |
| --- | --- | --- |
| Task Priority | RaiseTPL / RestoreTPL | 提升/恢复任务优先级 |
| Memory | AllocatePages / FreePages / AllocatePool / FreePool / GetMemoryMap | 页与池的内存管理 |
| Event & Timer | CreateEvent / SetTimer / WaitForEvent / SignalEvent / CloseEvent / CheckEvent | 事件与定时器 |
| Protocol Handler | Install / Handle / Locate / Open / Close Protocol | 协议的安装、查询、定位 |
| Image | LoadImage / StartImage / Exit / UnloadImage / ExitBootServices | 镜像加载、启动与退出 |
| Driver Support | ConnectController / DisconnectController | 驱动与设备的绑定/解绑 |
| Library | LocateProtocol / LocateHandleBuffer / ProtocolsPerHandle | 高级定位查询 |
| Misc | Stall / SetWatchdogTimer / CopyMem / SetMem / CalculateCrc32 | 延时、看门狗、内存操作、CRC |

## 3. 任务优先级 TPL

UEFI 没有传统硬件中断优先级机制，改用 TPL（Task Priority Level）控制"当前哪些任务可以运行"。`RaiseTPL` 提升当前优先级并返回旧值；高 TPL 会屏蔽低于它的任务。

> 与 MCU 的中断优先级机制类似：提升 TPL 相当于屏蔽低于该优先级的 IRQ。区别在于 UEFI 管理的是任务而非硬件中断。

层级由低到高：`TPL_APPLICATION`（最低，普通代码）→ `TPL_CALLBACK`（事件回调）→ `TPL_NOTIFY`（I/O 通知，可抢占 APPLICATION）→ `TPL_HIGH_LEVEL`（固件最高级，不可抢占，不可长时间占用）。数值上大致为 4 / 8 / 16 / 31。

核心约束：**Raise 与 Restore 必须成对，且在同一函数内完成**。遗漏 Restore 会导致低优先级任务被永久屏蔽、系统死锁。

```c
EFI_TPL OldTpl;
OldTpl = gBS->RaiseTPL(TPL_NOTIFY);   // 提升优先级，屏蔽低优先级任务
// 执行关键代码（应保持简短）
gBS->RestoreTPL(OldTpl);              // 恢复旧优先级
```

Notification 回调运行于 `CreateEvent` 时指定的 TPL。回调中只做轻量操作（设标志、入队），实质处理交由低 TPL 轮询完成。

## 4. 内存：Pages 与 Pool

内存管理分两层。Pages 以 4KB 为单位分配，适合大块连续内存；Pool 在页之上封装，适合小块动态分配。

```c
EFI_PHYSICAL_ADDRESS Memory;
Status = gBS->AllocatePages(
  AllocateAnyPages,
  EfiBootServicesData,
  4,            // 4 页 = 16KB
  &Memory);
gBS->FreePages(Memory, 4);   // 使用完毕
```

分配类型：`AllocateAnyPages`（系统任选地址）、`AllocateMaxAddress`（不高于指定地址）、`AllocateAddress`（固定地址，冲突失败）。`FreePages` 页数必须与分配一致，且只能释放 `AllocatePages` 分配的内存。

```c
VOID *Buffer;
Status = gBS->AllocatePool(EfiBootServicesData, 256, &Buffer);
ZeroMem(Buffer, 256);
gBS->FreePool(Buffer);
```

- 内存类型选 `EfiBootServicesData`：`ExitBootServices` 后 OS 回收，无需手动释放。需进 OS 后保留则用 `EfiRuntimeServicesData`（必须支持重定位，用 `ConvertPointer`）
- 另有 `EfiACPIMemoryNVS`、`EfiReservedMemoryType` 等特殊类型
- **调用 `ExitBootServices()` 前必须先获取最新的 memory map**，且 map 获取后仍可能变化，需配合重试循环：

```c
UINTN MapSize = 0;
gBS->GetMemoryMap(&MapSize, NULL, NULL, NULL, NULL); // 先查询所需大小
MapSize += sizeof(EFI_MEMORY_DESCRIPTOR);            // 预留一条余量
Status = gBS->GetMemoryMap(&MapSize, Map, &MapKey, &DescSize, &DescVer);
// 调用 ExitBootServices 时传入 MapKey
```

## 5. 事件与定时器

UEFI 不提供硬件 IRQ，所有异步机制基于 Event。每个事件只有触发态与未触发态两种状态。事件被触发时，按创建时指定的 TPL 执行 Notification 回调。

事件类型可通过 OR 组合：`EVT_TIMER`（定时器）、`EVT_NOTIFY_WAIT`（被 WaitForEvent 等待时触发）、`EVT_NOTIFY_SIGNAL`（被 SignalEvent 时触发）、`EVT_RUNTIME`（ExitBootServices 后仍可用）。

系统预定义信号宏：`EFI_EVENT_SIGNAL_READY_TO_BOOT`、`EFI_EVENT_SIGNAL_EXIT_BOOT_SERVICES`，在启动关键节点自动 Signal。

```c
EFI_EVENT Evt;
Status = gBS->CreateEvent(
  EFI_EVENT_SIGNAL_READY_TO_BOOT,
  TPL_CALLBACK,
  MyReadyToBootCallback,   // 回调函数
  NULL,
  &Evt);
```

`CreateEventEx` 比 `CreateEvent` 多一个 EventGroup 参数，可将事件归入组。组中任一事件被 Signal，组内所有 NOTIFY 回调依次排队执行。UEFI 预定义事件组：`EXIT_BOOT_SERVICES`、`VIRTUAL_ADDRESS_CHANGE`、`MEMORY_MAP_CHANGE`、`READY_TO_BOOT`。

等待有两种方式：`WaitForEvent(NumberOfEvents, Event[], &Index)` 阻塞等待直至任一事件触发并返回下标；`CheckEvent(Event)` 不阻塞，触发态返回 `EFI_SUCCESS`，未触发返回 `EFI_NOT_READY`。

定时器由 `SetTimer` 控制，**时间单位为 100ns**：

```c
gBS->SetTimer(TimerEvent, TimerPeriodic, 100000000);  // 每 10 秒触发一次
// 1 秒 = 10,000,000
```

`TimerPeriodic` 为周期触发，`TimerRelative` 为一次性触发。

> **RegisterProtocolNotify** 是常用机制：注册后，指定协议一旦被安装即自动 Signal 所注册的事件，常用于"驱动 A 安装协议后，驱动 B 收到通知继续执行"，避免主动轮询。

## 6. 协议处理

协议处理管理 Handle 与 Protocol 的安装和定位。先明确三个概念：**Controller**（设备）、**Handle**（绑定到设备/对象上的句柄）、**Protocol**（挂载于 Handle 上、以 GUID 标识的接口）。一个 Handle 可挂载多个协议。

常用函数：`InstallProtocolInterface`（安装）、`ReinstallProtocolInterface`（替换）、`UninstallProtocolInterface`（卸载）、`HandleProtocol`（获取接口）、`LocateHandle`/`LocateHandleBuffer`（按条件查找）、`LocateDevicePath`（按 DevicePath 查找）、`OpenProtocol`/`CloseProtocol`（带引用追踪，比 HandleProtocol 安全，应优先使用）、`InstallConfigurationTable`（安装系统配置表，如 SMBIOS、ACPI）。

```c
EFI_BLOCK_IO_PROTOCOL *BlockIo;
Status = gBS->HandleProtocol(
  Handle,
  &gEfiBlockIoProtocolGuid,
  (VOID **)&BlockIo);
```

- 全局查找协议优先用 `LocateProtocol(Guid, NULL, &Interface)`，单行获取第一个匹配接口
- `OpenProtocol` 优于 `HandleProtocol`：记录 AgentHandle 与 ControllerHandle，便于统一管理与避免重复打开；使用后应 `CloseProtocol`
- 常用协议：`EFI_BLOCK_IO_PROTOCOL`（磁盘读写）、`EFI_SIMPLE_FILE_SYSTEM_PROTOCOL`（文件读写）、`EFI_GRAPHICS_OUTPUT_PROTOCOL`（显示输出）。多在 DXE 阶段由对应驱动安装，模块通过 Locate 获取

## 7. 镜像服务

`LoadImage` 将 PE/COFF 镜像从文件或内存加载，返回 `ImageHandle`，但**不自动执行**；`StartImage` 才跳转到入口点。

`ExitBootServices` 是整个启动流程的分水岭：调用后所有 Boot Services 失效，控制权移交 OS，操作不可逆。调用之后不得再访问 `gBS` 中任意指针。

```c
Status = gBS->LoadImage(FALSE, ParentHandle, DevicePath, NULL, 0, &ImageHandle);
if (!EFI_ERROR(Status)) {
  Status = gBS->StartImage(ImageHandle, &ExitDataSize, &ExitData);
}
```

> `ExitBootServices` 必须与 memory map 配合。标准写法："获取 map → 调用 ExitBootServices → 若返回 `EFI_INVALID_PARAMETER` 说明 map 已变化 → 重新获取 map 再试"，循环直至成功。许多启动黑屏或卡住的问题源于此步骤未做重试。

## 8. 驱动支持 / 库函数 / 杂项

- **Driver Support**：`ConnectController` 绑定驱动到设备，`DisconnectController` 解除绑定。BDS 阶段依赖此机制完成驱动与设备的配对
- **Library 类**：`LocateProtocol` 全局查找、`LocateHandleBuffer` 批量定位、`ProtocolsPerHandle` 查询某 Handle 上挂载的协议
- **Misc 类**：`Stall`（微秒忙等待，占用 CPU）、`SetWatchdogTimer`（看门狗，默认 5 分钟）、`CopyMem`/`SetMem`（比 C 标准库可靠）、`GetNextMonotonicCount`（单调递增计数）、`CalculateCrc32`（数据完整性校验）

## 9. 需要注意的点

- **配对原则**：CreateEvent 配 CloseEvent，RaiseTPL 配 RestoreTPL，Allocate 配 Free，OpenProtocol 配 CloseProtocol。遗漏会导致资源泄漏或死锁
- **ExitBootServices 前获取最新 Memory Map**，该函数可能失败需重试。调用之后 `gBS` 全部失效
- **TPL 不可长时间保持高位**：高 TPL 屏蔽系统调度，仅应短暂使用
- **Notification 回调受限**：不应分配内存、创建新事件、执行耗时操作，仅做轻量处理
- **接口指针生命周期**：`HandleProtocol` 获取的指针仅在 Handle 有效期间可用。全局查找优先 `LocateProtocol`，`OpenProtocol` 优于 `HandleProtocol`
- **内存类型选择**：启动期数据用 `EfiBootServicesData`（OS 回收）；需进 OS 后保留的用 `EfiRuntimeServicesData`
