# Super I/O：IT8613E 架构、配置与 BIOS 实现

Super I/O（SIO）是主板上承接传统低速 I/O 的控制器芯片，串口（UART）、PS/2 键鼠（KBC）、GPIO、硬件监控（温度/电压/风扇）都由它管理。CPU 不直接访问 SIO，而是经 PCH 的 LPC/eSPI 总线间接访问；BIOS 要在 PEI 阶段尽早把它的寄存器配好，否则串口调试输出和 GPIO 状态在 POST 后期就用不上。本篇以 IT8613E 为主线，讲清 SIO 的访问模型（Index/Data + LDN）、GPIO/UART/KBC/EC 各子系统，以及 AMI BIOS 里表驱动式的 SIO 初始化代码。

## 一、SIO 在系统中的角色

SIO 集成了 CPU/PCH 不直接支持的低速外设接口：

| 功能 | 说明 |
| --- | --- |
| Serial Port (UART) | 串口通信，COM1/COM2，16C550 兼容 |
| KBC | PS/2 键盘/鼠标控制器，8042 兼容 |
| GPIO | 通用输入输出，IT8613E 有 7 组共 56 个引脚 |
| Hardware Monitor | 温度/电压/风扇转速监控与自动调速 |
| Consumer IR | 红外遥控接收 |
| Floppy / LPT | 软驱、并口（现代平台基本弃用） |

总线演进决定了 SIO 的接口形态：

```
ISA Bus (1981) → LPC Bus (1999) → eSPI Bus (2016)
  并行、引脚多      4-bit 复用、引脚少     SPI 物理层 + 通道化协议
```

当前平台：Intel Skylake 之后用 eSPI；AMD/海光平台 LPC 或 eSPI 都有。IT8613E 同时支持 LPC 和 eSPI，靠引脚配置选择。

> 不是所有平台都需要 SIO。笔记本的 EC（嵌入式控制器）已集成大部分 SIO 功能；部分服务器用 BMC 替代。台式机/工控机/工作站主板仍是 SIO 的主战场。

## 二、系统架构与总线：CPU–PCH–SIO

```
┌─────────┐  DMI/PCIe  ┌─────────┐  LPC/eSPI  ┌──────────────┐
│  CPU    │───────────►│  PCH    │───────────►│  SIO(IT8613E)│
└─────────┘            └─────────┘            └──────┬───────┘
                                                      │
                          UART/COM · GPIO · KBC(PS/2) · HWM · CIR
```

SIO 挂在 PCH 的 LPC 控制器（PCI Device 31:0）下面。BIOS 访问 SIO 端口时，实际走 PCH 的 LPC/eSPI 控制器，PCH 端必须对目标 IO 地址做了 Decode 使能，访问才有效。

### LPC 总线（Low Pin Count，Intel 1999 年推出）

- 数据线 `LAD[3:0]`，4-bit 地址/数据多路复用
- 控制线：`LCLK`（33 MHz）、`LFRAME#`（帧起始）、`LRESET#`
- 中断：`SERIRQ`（Serialized IRQ）串行传输
- 支持 8237 兼容 DMA（eSPI 不再支持）
- 理论带宽约 **16.67 MB/s**（33 MHz × 4 bit）

### eSPI 总线（Enhanced SPI，Intel 2016 年推出）

- 信号：`CS#`、`CLK`、`IO[0..3]`、`ALERT#`、`RESET#`，最少 2 根数据线（x1 模式）
- 频率最高 66 MHz，x4 模式理论带宽约 **33 MB/s**
- 协议层划分 4 个逻辑通道（同一物理总线复用）：

| 通道 | 编号 | 用途 |
| --- | --- | --- |
| Peripheral | 0 | I/O 与 Memory 读写——SIO 寄存器访问、legacy I/O 仿真 |
| Virtual Wire | 1 | 传输侧带信号：SCI、SMI#、RCIN#、SLP_S3#/SLP_S4# 等改为"虚拟线"报文 |
| Out-of-Band | 2 | SMBus 隧道，BMC 带外管理 |
| Flash Access | 3 | 从机（EC）直接访问共享 SPI Flash |

## 三、IT8613E 芯片概述

ITE 的 EC-LPC I/O 控制器，64-LQFP（10×10 mm），3.3V 供电（部分引脚 5V 容忍）。

| Feature | Specification |
| --- | --- |
| Bus Interface | LPC & eSPI |
| Serial Port | 1 路 UART（16C550） |
| GPIO | 7 组（56 pins） |
| Temperature | 6 路 TMPIN 输入 |
| Voltage | 5 路 VIN + 3 路固定（3VSB/VBAT/AVCC3） |
| Fan Control | 4 组 SmartGuardian |
| KBC | Keyboard + Mouse |
| CIR | Consumer IR 1 路 |
| 其他 | Watchdog、PECI / SB-TSI 接口、Breath LED、ACPI 电源控制、时钟发生器 |

> 芯片确认方法：配置模式下读 Index 0x20/0x21 得到 Chip ID1=0x86、ID2=0x13，即 0x8613 → IT8613 系列。代码里做 SIO 探测通常就靠这两步。

## 四、SIO 配置体系：Index/Data、全局寄存器、LDN

### 4.1 访问模型

SIO 配置空间通过一对 IO 端口访问（ITE 系标准）：

| 端口 | 地址 | 作用 |
| --- | --- | --- |
| Index Port | 0x2E | 写寄存器偏移 |
| Data Port | 0x2F | 读写该偏移的数据 |

> 部分芯片用 0x4E/0x4F 作为另一组配置端口（Nuvoton 系常见 0x2E 或 0x4E）。解锁口令与端口相关：0x2E 口用 `87 01 55 55` 结尾，0x4E 口用 `87 01 55 AA`——实训工程 IT8786 的代码里就有这个 `#if` 分支。

地址空间分三段：
- **Global Register（0x00~0x2F）**：全局共享，芯片级配置（Chip ID、LDN 选择、软件复位、Lock）
- **LDN Register（0x30~0xFF）**：按逻辑设备独立，每个 LDN 有自己的基址/IRQ/使能
- **EC Register（Bank0/1/2）**：环境控制器专用，经 EC 自己的 Index/Data 端口访问

### 4.2 LDN（Logical Device Number）

SIO 用 LDN 把内部不同外设组织成"逻辑设备"：向 Index=0x07 写入 LDN 号即选中该设备，之后访问的 0x30~0xFF 都是它的私有寄存器。切换设备前必须先解锁。

IT8613E 的 LDN 表：

| LDN | 设备 | Base Offset | Activate | 说明 |
| --- | --- | --- | --- | --- |
| 00h | Floppy | 60h/61h | 30h | 软驱控制器（通常禁用） |
| 01h | Serial Port 1 | 60h/61h | 30h | COM1 UART |
| 02h | Serial Port 2 | 60h/61h | 30h | COM2 UART（若支持） |
| 04h | Env. Controller | 60h/61h | 30h | HWM：温度/电压/风扇 |
| 05h | KBC Keyboard | 60h/61h, 62h/63h | 30h | PS/2 键盘 |
| 06h | KBC Mouse | — | 30h | PS/2 鼠标（共享 KB 端口） |
| 07h | GPIO | 60h/61h, 62h/63h | — | 7 组 GPIO |
| 0Ah | Consumer IR | 60h/61h | 30h | 红外接收 |

关键偏移约定：**0x30 Activate**（bit0=1 使能）、**0x60/0x61 第一组基址**（Hi/Lo）、**0x62/0x63 第二组基址**、**0x70 IRQ**。

### 4.3 完整访问流程

```c
// 1. Unlock（进配置模式，0x2E 口固定口令）
IoWrite8(0x2E, 0x87); IoWrite8(0x2E, 0x01);
IoWrite8(0x2E, 0x55); IoWrite8(0x2E, 0x55);

// 2. 选择 LDN（例：GPIO = 07h）
IoWrite8(0x2E, 0x07);   // Index Port: 写寄存器偏移 0x07
IoWrite8(0x2F, 0x07);   // Data Port:  写 LDN 值

// 3. 读写目标寄存器（例：读 Chip ID1）
IoWrite8(0x2E, 0x20);   // 选择寄存器 0x20
chip_id1 = IoRead8(0x2F); // → 0x86

// 4. Lock（出配置模式）
IoWrite8(0x2E, 0x02);   // Index = 0x02（Global Lock）
IoWrite8(0x2F, 0x02);   // bit1=1 → 锁定 SIO
```

配置 COM1 基址的完整例子：

```c
IoWrite8(0x2E, 0x07); IoWrite8(0x2F, 0x01); // LDN=01h (UART)
IoWrite8(0x2E, 0x60); IoWrite8(0x2F, 0x03); // Base MSB = 0x03
IoWrite8(0x2E, 0x61); IoWrite8(0x2F, 0xF8); // Base LSB = 0xF8 → 0x03F8
IoWrite8(0x2E, 0x70); IoWrite8(0x2F, 0x04); // IRQ = 4
IoWrite8(0x2E, 0x30); IoWrite8(0x2F, 0x01); // Activate（bit0=1）
```

> [!warning]
> 基址必须落在 PCH LPC/eSPI 的 Decode 范围内，否则 CPU 侧的 IO 访问到不了 SIO。配 SIO 之前先确认 PCH 侧 Decode 路由——工程里这步由 `AmiSioLibSetLpcDeviceDecoding()` 完成。

## 五、GPIO 子系统

IT8613E 有 7 组 GPIO（GPIO1X~GPIO6X + GPIOAX），每组 8 个引脚，全部在 LDN=07h 下配置。每个引脚可在两种模式间切换：**Function Mode**（复用功能）与 **Simple I/O Mode**（普通 GPIO 输入/输出）。

各组关键寄存器：

| Group | Pins | Multi-Func Reg | Enable Reg | Direction Reg |
| --- | --- | --- | --- | --- |
| GPIO1X | GP10~GP17 | 0x25 | 0xC0 | 0xC7 |
| GPIO2X | GP20~GP27 | 0x26 | 0xC1 | 0xC8 |
| GPIO3X | GP30~GP37 | 0x27 | 0xC2 | 0xC9 |
| GPIO4X | GP40~GP47 | 0x28 | 0xC3 | 0xCA |
| GPIO5X | GP50~GP57 | 0x29 | 0xC4 | 0xCB |
| GPIO6X | GP60~GP67 | 0x2A | 0xC5 | 0xCC |
| GPIOAX | GPA0~GPA7 | 0x2B | 0xC6 | 0xCD |

配置流程固定四步：**Pin 功能选择 → Enable 使能 → Direction 方向 → 数据读写**。

```c
// 把 GP43 配成 GPIO Input（完整流程）
IoWrite8(0x2E, 0x07); IoWrite8(0x2F, 0x07);  // LDN=07h (GPIO)

// Step1: Pin 选择为 GPIO mode（Multi-Func Reg 0x28, bit3=1）
IoWrite8(0x2E, 0x28); Data = IoRead8(0x2F);
IoWrite8(0x2F, Data | BIT3);

// Step2: 使能 GP43（Enable Reg 0xC3, bit3=1）
IoWrite8(0x2E, 0xC3); Data = IoRead8(0x2F);
IoWrite8(0x2F, Data | BIT3);

// Step3: 方向为 Input（Direction Reg 0xCA, bit3=0）
IoWrite8(0x2E, 0xCA); Data = IoRead8(0x2F);
IoWrite8(0x2F, Data & ~BIT3);

// Step4: 读 GP43（GPIO Base 由 LDN07 的 0x62/0x63 给出，通常 0xA00）
Value = (IoRead8(0xA03) >> 3) & 0x01;
```

> 这套"复用选择 + 使能 + 方向 + 读写"与 MCU 的 GPIO 完全同构：Multi-Func 寄存器 ≈ STM32 的 AFRL/AFRH，Direction 寄存器 ≈ MODER/CRL，Data 寄存器 ≈ IDR/ODR。唯一区别是 SIO 的寄存器藏在 Index/Data 后面，要先解锁才能碰。

GPIO 数据口直接映射在 GPIO Base 上：Base+0x00 起按组排列，bit 对应组内引脚。例子里 `0xA03` 即 GPIO4X 的数据寄存器（Base 0xA00 + 3）。

## 六、UART 串口与 KBC

### 6.1 Serial Port（LDN=01h，16C550 兼容）

- 默认基址 0x3F8（COM1），IRQ4
- 内部是标准 16C550 UART 寄存器集，相对基址偏移：

| 偏移 | 寄存器 | 说明 |
| --- | --- | --- |
| +0 | RBR/THR/DLL | 接收缓冲/发送保持/除数低字节（DLAB=1 时） |
| +1 | IER/DLM | 中断使能/除数高字节 |
| +2 | IIR/FCR | 中断标识/FIFO 控制 |
| +3 | LCR | 线路控制（含 DLAB 位） |
| +4 | MCR | Modem 控制 |
| +5 | LSR | 线路状态（THRE、RDR 等） |
| +7 | SCR | 暂存 |

波特率由除数锁存器决定：`Divisor = 115200 / Baud`（16C550 时钟 1.8432 MHz，实际是 `1843200 / (16 × Baud)`）。115200 baud 时 Divisor=1。

### 6.2 KBC（LDN=05h/06h，8042 兼容）

- Keyboard：Data Port 0x60、Command/Status Port 0x64，IRQ1
- Mouse：与键盘共享 IO 端口，IRQ12
- BIOS 在 DXE 阶段通过 ACPI 表把 KBC 设备注册给 OS

```c
// KBC 基址配置示例
IoWrite8(0x2E, 0x07); IoWrite8(0x2F, 0x05); // LDN=05h (KB)
IoWrite8(0x2E, 0x60); IoWrite8(0x2F, 0x00); // Data Port MSB
IoWrite8(0x2E, 0x61); IoWrite8(0x2F, 0x60); // Data Port LSB = 0x60
IoWrite8(0x2E, 0x62); IoWrite8(0x2F, 0x00); // Cmd Port MSB
IoWrite8(0x2E, 0x63); IoWrite8(0x2F, 0x64); // Cmd Port LSB = 0x64
IoWrite8(0x2E, 0x30); IoWrite8(0x2F, 0x01); // Activate KB
```

> UART 和 KBC 是 POST 早期必须就位的资源：COM1（0x3F8）是串口调试输出（Debug Port）的默认位置，PEI 阶段 SerialPortLib 打印就走它；KBC 的 0x60/0x64 是 PS/2 设备的标准地址。SIO 初始化晚于这些端口被使用，会出现"串口没输出"的典型故障。

## 七、环境控制器 EC（HWM：温度/电压/风扇）

EC 是 SIO 里最复杂的子系统（LDN=04h），用独立的 Index/Data 端口访问：**Index = EC Base + 0x05，Data = EC Base + 0x06**（EC Base 通常 0xA00）。EC 内部按 Bank 组织寄存器页（Bank0/1/2），切换 Bank 写 Index=0x4E。

### 7.1 温度监控（6 路 TMPIN）

- 数据寄存器 0x25~0x2A（Bank0，只读），有符号数，单位 °C
- 每路 TMPIN 的温度来源由 Index 0x1D 选择：

| Code | 来源 | 平台 | 硬件 |
| --- | --- | --- | --- |
| 0000b | Disable | — | — |
| 0001b | Thermal Diode (TD) | 通用 | Pin 45/46 |
| 0010b | Thermistor (TR) | 通用 | Pin 45/46 |
| 0011b | SB-TSI / SM-Host | AMD/海光 | Pin 26/27 |
| 0100b | PECI | Intel | PECI Pin |

温度来源必须对照硬件原理图确认——选错来源，读数就是乱码或恒值。

> 两种 CPU 温度接口：
> - **PECI**（Intel Platform Environment Control Interface）：Intel 单线温度/控制接口，命令式协议（GetTemp 等），SIO 通过 PECI pin 直接问 CPU 的 DTS 温度
> - **SB-TSI**（AMD SideBand Temperature Sensor Interface）：AMD/海光 CPU 的侧带温度接口，基于类似 SMBus 的三线协议，SIO 作为 TSI 主设备按从机地址读取 CPU 温度

### 7.2 电压监控（5+3 路 VIN）

| Channel | Reg (Bank0) | 换算公式 | 范围 | 类型 |
| --- | --- | --- | --- | --- |
| VIN0 | 0x20 | Value × 10.9 mV | 0~2.78V | 自定义 |
| VIN1 | 0x21 | Value × 10.9 mV | 0~2.78V | 自定义 |
| VIN2 | 0x22 | Value × 10.9 mV | 0~2.78V | 自定义 |
| VIN4 | 0x23 | Value × 10.9 mV | 0~2.78V | 自定义 |
| VIN5 | 0x24 | Value × 10.9 mV | 0~2.78V | 自定义 |
| Internal 3VSB | 0x25 | Value × 21.8 mV | 0~5.56V | 固定 |
| VBAT | 0x26 | Value × 21.8 mV | 0~5.56V | 固定 |
| Internal AVCC3 | 0x27 | Value × 21.8 mV | 0~5.56V | 固定 |

自定义通道若有板级分压，读数还要乘硬件倍数。PPT 实例（OPS71C-SHH 项目 VIN5）：Reading=0x8A(138)，基础电压 = 138 × 10.9 mV = 1.504V，乘分压倍数 1.65 → 实际 2.48V。注意 IT8613E 无 VIN3。

> [!warning]
> 读数全 0 或全 FF 的排查顺序：① 使能寄存器是否置位；② 硬件连接；③ ADC Reference。VIN 通道使用前先确认 Enable。

### 7.3 风扇控制（SmartGuardian）

基于温度的自动 PWM 调速：三个温度阈值 + 斜率。

```
Temp < Off      → PWM = 0（停转）
Off ~ Start     → 起转 PWM（最小占空比）
Start ~ Full    → 线性调节（Slope）
Temp > Full     → PWM = 100%
```

FAN2 的关键寄存器（Bank0）：Enable 0x13 bit5、PWM Control 0x6B（温度来源 bit5-3 + Mode bit7）、Start PWM 0x6B/0x73、Temp Limit Off 0x68、Start 0x69、Full 0x6A、Slope 0x6C。

配置 FAN2 的完整例子（散热参数从散热工程师的 Fan Table 拿）：

```c
// Step1: GP51/GP52 设为 Function mode（风扇信号复用）
IoWrite8(0x2E, 0x29); Data = IoRead8(0x2F);
IoWrite8(0x2F, Data & 0xF9);      // GP51,GP52 = Func

// Step2: 写风扇寄存器
SioWrite(0, 0x6B, 0x33);  // PWM Ctrl: TMPIN1, Auto
SioWrite(0, 0x68, 0x28);  // Off  = 40°C
SioWrite(0, 0x69, 0x32);  // Start= 50°C
SioWrite(0, 0x6A, 0x5A);  // Full = 90°C
SioWrite(0, 0x6C, 0x96);  // Slope
SioWrite(0, 0x13, SioRead(0, 0x13) | BIT5); // Enable
```

EC 访问总流程：

```c
// 1. LDN=04h 配 EC Base（通常 0xA00）
// 2. Index=Base+5, Data=Base+6
IoWrite8(0xA05, 0x20); val = IoRead8(0xA06);   // 读 VIN0
// 3. Bank 切换：Index=0x4E → 0x00=Bank0, 0x01=Bank1, 0x02=Bank2
```

## 八、电源管理与 ACPI

IT8613E 提供一组 ACPI 电源信号（Spec 第 11 章有时序图）：PWRGD1/2/3、PCIRST#1/2/3、RSMRST#、PWRON#（电源键输入）、SLP_SUS#、DPWROK。

BIOS 各阶段对 SIO 的操作顺序：

```
SEC → PEI（SIO Init）→ DXE（HWM/ACPI）→ BDS → OS Runtime
```

- **PEI 阶段**：解锁 SIO → 配各 LDN 基址 → 配 GPIO 初始状态 → Lock。必须最早做，因为 PEI 后期串口调试（COM1）和 GPIO 就要用了
- **DXE 阶段**：初始化 UART（Debug Port）、注册 ACPI 设备（KBC/UART）、配置 HWM
- **EuP 支持**：S5（Soft Off）下 SIO 控制主板进入极低功耗模式

> 与 ACPI、SMI 笔记串起来看：S0/S3/S4/S5 睡眠状态切换时，PCH 输出的 SLP_S3#/SLP_S4# 经 eSPI Virtual Wire 通道到达从机（SIO/EC）；进入睡眠瞬间，SMI 笔记里 OemSmi 驱动的 Sx Handler 在 SMM 里操作 IT8786 GPIO 设置电源 LED（S3 呼吸灯、S4/S5 常亮）——同一颗 SIO 芯片，PEI 阶段由 BIOS 表驱动配置，运行期由 SMM 按需改写。LED/AC 策略这类"睡后仍生效"的操作必须放 SMM。

## 九、BIOS 实现：表驱动 SIO 初始化

### 9.1 OemPeiIoTable.c 的 IT8613PeiInitTable

AMI BIOS 中 SIO 初始化是**表驱动**的：把所有寄存器写操作组织成 `IO_TABLE_ENTRY {Port, AndMask, OrValue}` 三元组数组，PEI 阶段一个遍历函数按序执行，`Output = (Input & AndMask) | OrValue`。

```c
// OemPeiIoTable.c — IT8613 SIO 初始化配置表（框架）
IO_TABLE_ENTRY IT8613PeiInitTable[] = {
  // 1. Decode（解锁）
  {IT8613_CONFIG_INDEX, 0x00, 0x87},
  {IT8613_CONFIG_INDEX, 0x00, 0x01},
  {IT8613_CONFIG_INDEX, 0x00, 0x55},
  {IT8613_CONFIG_INDEX, 0x00, 0x55},
  // 2. LDN Select + EC Base（LDN=04）
  {IT8613_CONFIG_INDEX, 0x00, IT8613_LDN_SEL_REGISTER}, // Index=07
  {IT8613_CONFIG_DATA,  0x00, IT8613_LDN_ENV},           // LDN=04
  {IT8613_CONFIG_INDEX, 0x00, IT8613_BASE1_HI_REGISTER}, // Index=60
  {IT8613_CONFIG_DATA,  0x00, (UINT8)(IT8613_HWM_BASE >> 8)},
  {IT8613_CONFIG_INDEX, 0x00, IT8613_BASE1_LO_REGISTER}, // Index=61
  {IT8613_CONFIG_DATA,  0x00, (UINT8)(IT8613_HWM_BASE & 0xFF)},
  // 3. GPIO（LDN=07）...
  // 4. EC 温度源（TMPIN1 = SB-TSI）
  {IT8613_HWM_INDEX_PORT, 0x00, 0x1D},
  {IT8613_HWM_DATA_PORT,  0xF0, 0x03},
  // 5. Fan 配置 ...
  // 终止标记
  {0xFFFF, 0x00, 0x00}
};
```

约定：`Port=0xFFFF` 为终止标记；`AndMask=0x00` 表示直接写 OrValue（跳过读改写）。新增 SIO 功能只需追加三元组，遍历逻辑不动。

### 9.2 实训工程对照：AmiModulePkg/IO/IT8786

实训平台（`C:\TEST\ib.iw68.xa03`）实际用的是 **IT8786** 而非 IT8613，但模型一致。`AmiModulePkg\IO\IT8786\IT8786PeiInit.c` 的入口：

```c
EFI_STATUS IT8786PeiInitEntryPoint(...)
{
    // ① 先设 PCH 侧 LPC Decode，让 SIO 端口能到达
    for (index = 0; index < sizeof(IT8786PeiDecodeTable)/sizeof(IO_DECODE_DATA); index++)
        AmiSioLibSetLpcDeviceDecoding(NULL,
            IT8786PeiDecodeTable[index].BaseAdd,
            IT8786PeiDecodeTable[index].UID,
            IT8786PeiDecodeTable[index].Type);

    // ② 表驱动写 SIO 寄存器（IO_TABLE_ENTRY 数组）
    ProgramRtRegisterTable(0, IT8786PeiInitTable,
        sizeof(IT8786PeiInitTable)/sizeof(SIO_DEVICE_INIT_DATA));

    // ③ 进配置模式（解锁口令：0x2E 口 87 01 55 55，0x4E 口 87 01 55 AA）
    IoWrite8(IT8786_CONFIG_INDEX, 0x87);
    IoWrite8(IT8786_CONFIG_INDEX, 0x01);
    IoWrite8(IT8786_CONFIG_INDEX, 0x55);
    #if (IT8786_CONFIG_INDEX == 0x2E)
    IoWrite8(IT8786_CONFIG_INDEX, 0x55);
    #else
    IoWrite8(IT8786_CONFIG_INDEX, 0xAA);
    #endif

    // ④ 禁用 PEI 阶段不用的设备（清 Base/IRQ/Activate）
    IT8786_PeiClearDevResource(IT8786_LDN_UART3);
    IT8786_PeiClearDevResource(IT8786_LDN_UART4);
    ...
}
```

要点：
- **`AmiSioLibSetLpcDeviceDecoding()` 对应 4.3 节的 warning**：先让 PCH 对目标 IO 窗口做 Decode 使能，SIO 端口访问才有效。Decode 表（`IT8786PeiDecodeTable`）是项目级配置
- `IT8786_CONFIG_INDEX`、`IT8786_LDN_SEL_REGISTER` 等宏由 **SDL Token 构建期生成**（`AmiModulePkg\IO\IT8786\IT8786.sdl`，`TargetH = Yes`），源码里找不到 `#define`——机制与 Library Mapping 笔记的 AMISDL 构建流程一致
- 同目录还有 `IT8786PlatformHookSerialPortLib.c`：实现 EDK II 的 **PlatformHookSerialPortLib**，为 `SerialPortLib` 提供串口基址/类型参数，即"PEI 阶段串口 Debug Port 从哪来"的答案
- SMI 笔记里的 `OemSmi.c` 运行期操作同一颗 IT8786 的 GPIO 做 LED/AC 策略（`S4S5PowerLed` 的三步套路：解锁 → LDN=07 → 改寄存器 → 锁回），与这里 PEI 的表驱动初始化一脉相承

> SIO 驱动不属于 EDK II 主线源码——EDK II 只有通用框架（SerialPortLib、PlatformHookLib、PCD），SIO 芯片的具体初始化是板级/厂商私有的（AMI 放 AmiModulePkg/IO）。查代码时先找 `PcdSerialRegisterBase`、`PlatformHookSerialPortLib` 这类抽象点，再往下追厂商实现。

Linux 下读 Chip ID 示例：

```c
outb(0x87, 0x2E); outb(0x01, 0x2E); outb(0x55, 0x2E); outb(0x55, 0x2E); // Decode
outb(0x20, 0x2E);                                  // Index = ChipID1

```

常见故障排查：

| 问题现象 | 可能原因 | 排查方法 |
| --- | --- | --- |
| IO 读取返回 0xFF | SIO 未 Decode，或 Base 不在 LPC Decode 范围 | 检查解锁序列 + SOC LPC Decode 表 |
| GPIO 状态异常 | Pin 未切 GPIO mode 或未使能 | 查 Multi-Func Reg + Enable Reg |
| 温度读数异常 | TMPIN 来源选错 / 硬件未接 | 确认 0x1D + 原理图 |
| 风扇不转 | GPIO 未设 Function / FAN 未使能 | 查 GP51/52 配置 + Enable 寄存器 |
| UART 无输出 | Base 冲突 / IRQ 错误 | 查 0x3F8 占用 + IRQ 设置 |

## 术语表

- **SIO（Super I/O）**：集成串口/键鼠/GPIO/硬件监控等低速 I/O 的控制器芯片
- **LPC（Low Pin Count）**：Intel 1999 年推出的 4-bit 复用总线，替代 ISA，33 MHz，约 16.67 MB/s
- **eSPI（Enhanced SPI）**：Intel 2016 年推出的 LPC 替代总线，SPI 物理层 + 4 通道协议，最高 66 MHz×4bit
- **Index/Data Port**：SIO 配置端口对（如 0x2E/0x2F），Index 选寄存器、Data 读写数据
- **LDN（Logical Device Number）**：SIO 内部逻辑设备编号，Index 0x07 写入后切换设备
- **Decode 序列**：进配置模式的口令（IT87xx 系：0x2E 口 `87 01 55 55`，0x4E 口 `87 01 55 AA`）
- **Activate（0x30）**：逻辑设备使能寄存器，bit0=1 使能
- **HWM（Hardware Monitor）**：环境监控，温度/电压/风扇转速采集
- **TMPIN**：SIO 温度输入通道，来源可配（TD/TR/SB-TSI/PECI）
- **SmartGuardian**：ITE 的智能风扇控制，基于 Off/Start/Full 三阈值 + Slope 的自动 PWM
- **KBC**：键盘/鼠标控制器，8042 兼容，端口 0x60/0x64
- **16C550**：标准 UART 内核，FIFO 16 字节，寄存器集事实标准
- **PECI**：Intel 单线温度/控制接口，命令式协议
- **SB-TSI**：AMD/海光 CPU 侧带温度传感器接口，SMBus 类似协议
- **IO_TABLE_ENTRY**：AMI SIO 初始化三元组 `{Port, AndMask, OrValue}`，表驱动配置的原子项
- **EuP**：Energy-using Products 节能规范，S5 下极低功耗模式
- **CIR（Consumer IR）**：消费红外接收接口
