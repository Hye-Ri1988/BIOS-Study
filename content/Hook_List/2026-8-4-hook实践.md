# TSE Hook 实践记录：SignOn 界面通过 Hook 打印内容

## 41 个 TSE Hook：定位与机制

41 个 Hook = TSE 的 **HOOK1 ~ HOOK41 锚点**（HOOK0 是列表末尾哨兵，后跟 LastTSEHook）。每个锚点是 boot flow 上的一个关键节点，节点下可挂 1~10 个函数，执行到该节点时按顺序全部调用。

### 41 个锚点完整清单（按 boot flow 分组）

- **阶段 ① 开机/POST**：HOOK1 画Logo、HOOK2 键盘可用、HOOK6 PostManager握手、HOOK33 屏幕可用、**HOOK35 画面就绪**、HOOK37 切回POST
- **阶段 ② 进 Setup**：**HOOK3 进Setup**、HOOK4 继续启动、HOOK5 驱动入口、HOOK38 判定进Setup、HOOK40 Setup重入
- **阶段 ③ Setup 运行**：HOOK7 按键映射、HOOK8 按键轮询、HOOK16-19 OEM键1-4、HOOK20 密码编码、HOOK21 控件配色、HOOK26 配置修改、HOOK31 鼠标映射、HOOK41 页面切换
- **阶段 ④ 保存/默认值**：**HOOK13 保存配置**、**HOOK14 载入默认**、HOOK23 用户默认、HOOK24 出厂默认、HOOK25 上次值、HOOK27 弹窗、HOOK29 Setup默认载入
- **阶段 ⑤ 启动OS/收尾**：HOOK9/10 Legacy启动前后、**HOOK11/12 EFI启动前后**、HOOK15 超时循环、HOOK22 无效按键、HOOK28 BBS启动、**HOOK30 复位前**、HOOK32 立即启动、HOOK39 BootFlow退出

每个锚点的默认实现函数名见 HookAnchor.h，官方语义看 AMITSE.sdl 里对应 ELINK 的 Help 文本。

## Hook 常用场景

| 业务需求 | 挂到 |
|---|---|
| SignOn 画面显示内容 | HOOK35（画面就绪） |
| 开机画 Logo 前后 | HOOK1 |
| 进 Setup 时 | HOOK3 |
| 启动 OS 前拦截/打印 | HOOK11/12（EFI）、HOOK9/10（Legacy） |
| 保存配置时 | HOOK13 |
| 载入默认值时 | HOOK14 / 23 / 24 / 25 / 29 |
| 拦截/过滤按键 | HOOK8（轮询）、HOOK7（映射） |
| OEM 快捷键 | HOOK16~19 |
| 复位前收尾 | HOOK30 |
| Setup 页面切换 | HOOK41 |

## 两种实现方式

**方式 A：直接在 AMI 官方预留的空函数体中进行改动**

直接改 `commonoem.c` 的 `AfterInitPostScreen()` 空函数体。官方注释写的就是 "OEMs may choose to do additional logic here"。

**方式 B：自定义函数 + elink 挂载**

该函数写在 AmiTsePkg/Core/em/AMITSE/commonoem.c 中：

```c
VOID MySignOnPrintHook(VOID)
{
    PostManagerDisplayPostMessage(L"[JYTian] Hook35 ELINK : Custom Hook!");
}
```

函数声明在 HookAnchor.h 中。AMITSE.sdl 的 AMITSE_Hooks 组加：

```sdl
ELINK
    Name  = "MySignOnPrintHook,"
    Parent  = "HOOK35,"
    Priority  = 35
    InvokeOrder = AfterParent
End
```

## 自定义函数必须能被 TSE 链接到

elink 挂载的函数**不能写在 OemJYTianPkg 的独立 DXE 驱动里**——驱动是独立 .efi，TSE 是另一个 .efi，链接器不跨 efi 解析符号，`make` 会报 undefined symbol。合法位置只有：TSE 源码树内（如 commonoem.c）或 TSE 链接的库（AMI 自己的 AmiTcgInstallPpiGuid、TbtSetupEnterHook 都是这么挂的）。
